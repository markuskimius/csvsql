# CLAUDE.md

Guidance for Claude Code when working with this repository.

## What This Is

CSVSQL is a browser-based CSV database: CSV files become SQL-queryable tables with editable cells in a multi-window interface. No build step or server required — open `index.html` directly in a browser. Also distributed via PyPI (`pip install csvsql`).

## Privacy Guarantee (hard constraint)

The app MUST NEVER send user data to any server or website. No telemetry, no analytics, no CDN loads at runtime (all dependencies are bundled in `lib/`), no background network requests of any kind. The only permitted network activity is explicitly user-initiated: (1) **File → Open URL** fetches the URL the user typed; (2) the AI assistant — which is **hidden by default** and only revealed by holding Shift while the page loads (see AI unlock in Conventions) — contacts Ollama (local) or a cloud provider (Claude, OpenAI, Gemini, or Grok) only when the user has configured that provider with their own API key. While AI is hidden, the app must make no AI-related network activity at all (not even the Ollama localhost probe in `detectAIProvider`). Never add a feature that violates this, and this promise is stated on the empty-state welcome screen, in the in-app manual (Privacy section), and in README.md — keep all three in sync if the network behavior ever changes. The AI feature is deliberately **undocumented** in README.md and the in-app manual (owner's decision): their privacy statements mention only Open URL, with no AI reference; only the unlocked welcome-message variant and this file mention AI. Don't re-add AI documentation to README or the manual.

## Architecture

Single-page app with three core files:

- **index.html** — Shell: menubar, workspace area (with `#empty-state` welcome screen), SQL console panel, hidden file input, CDN script tags. File menu order: New Table, Open..., Open (no header)..., Open URL..., Open URL (no header)..., Save Table, Save Table As..., Close Window. `updateMenuState()` runs at menu-open time: Save/Save As enabled only for table windows (`!!t` — Manual/About/Expression Reference don't count), Close Window for any window (`!!activeWinId`), layout buttons via `hasAny`
- **style.css** — Dark theme styling, window management visuals, table layout
- **app.js** — All application logic in a single IIFE (`app` module), exposing methods on the global `app` object

### Key dependencies (bundled in `lib/` — no CDN or internet required at runtime)

- **Papa Parse** — CSV parsing/unparsing
- **sql.js** — SQLite compiled to WebAssembly; each opened CSV is registered as a SQLite table
- **SheetJS (XLSX)** — Excel file reading/writing
- **JSZip** — ZIP archive support
- **Chart.js** — Inline chart rendering (lazy-loaded on first AI chart)
- **jsPDF + autotable** — PDF report generation (lazy-loaded on first AI PDF)
- **@mlc-ai/web-llm** — In-browser LLM inference via WebGPU (lazy-loaded)

### Data flow

1. CSV opened via File menu → Papa Parse parses → stored in `tables[name]` object (columns, rows, filename, modified flag)
2. Table registered in SQLite via `CREATE TABLE` + batch `INSERT` with prepared statements
3. Edits to cells update `tables[name].rows` and sync back to SQLite via `syncToSQL()`
4. SQL queries run against SQLite; results become new entries in `tables` and open in new subwindows
5. Save serializes `tables[name]` back to CSV via Papa.unparse and triggers browser download

### Window management

Custom subwindow system — each table/query result gets a draggable, resizable, minimizable window inside `#window-area`. Drag, resize, and keyboard nudge all clamp to the `#window-area` bounds. All mouse-driven interactions require the left button only (`e.button !== 0` guard); right/middle click on data cells calls `e.preventDefault()`. During drag and resize, windows snap to workspace and other window edges within `SNAP_THRESHOLD` (10 px) with blue guide lines — helpers: `getSnapEdges(excludeWin)`, `findSnap`, `snapPosition()`, `showSnapGuides`/`hideSnapGuides`. Dragging the titlebar of a maximized window (or the tab bar of a maximized dock) restores its `prevBounds` via `unmaximizeForDrag()` (grab point stays proportional; a click without movement does not unmaximize); resizing a maximized window/dock clears the `maximized` flag. Layout functions (tile, grid, cascade) reposition all visible windows; `scaleWindowsToArea()` rescales proportionally on browser/console resize. Windows track their own sort/filter state and column autofilters. The `windows` array and `tables` object are the two central data structures.

### Tabbing and docking

Windows can be combined into dock containers via tabbing and docking. A dock container is a `.dock-container` element positioned in `#window-area` like a `.subwindow`, with its own resize handles, maximize/minimize support, and a recursive binary split tree for layout.

**Data model:** `dockContainers[]` array holds dock containers. Each has a `root` DockNode — either a leaf (tab group) or a split node. Split nodes have `direction` ('horizontal'|'vertical'), `ratio` (0.0–1.0), and two children. Leaf nodes have `tabs` (array of window IDs), `activeTab`, and DOM references (`el`, `tabBarEl`, `contentEl`). Window objects gain `dockId` (null or dock container ID), `dockLeaf` (reference to containing leaf), and `dockable` (false for help/about windows).

**Tabbing:** Hold Shift and drag a window's titlebar onto another window's titlebar area to merge them into a tab group. Tabs are content-width (fit their text) rather than stretching equally. Only 1 level of tabbing (tab groups cannot be nested inside tab groups, but each pane in a dock split can be its own tab group). The active tab's `.win-body` and `.win-statusbar` are visible; inactive tabs' content is hidden via `display: none` with `dataset.winId` for identification. Double-clicking a tab toggles maximize/restore on the dock container. Single-tab leaves inside a split hide their tab bar (class `single-tab`) but the tab shrinks to content width; the tab bar reappears when a second tab is added. Tabs can be reordered by dragging left/right within the same tab bar (no Shift needed) — the dragged tab dims and a blue insertion indicator shows the drop position. A `::after` pseudo-element gives the tab bar a 40px min grab area right of the tabs so the dock can always be dragged.

**Docking:** Hold Shift and drop a window onto the body area of another window to create a split dock. Without Shift, dragging just moves the window normally. Drop zone detection: the body area (below titlebar/tab-bar) is divided into 4 triangular zones by its diagonals, determining top/right/bottom/left. Dropping on the titlebar or tab bar triggers tabbing (center zone) with position-aware insertion — `detectDropTarget` computes `tabIndex` from cursor X relative to existing tab midpoints, `showDropOverlay` renders a `.dock-drop-tab-indicator` vertical line at the insertion point, and `dockWindowAsTab(winId, leaf, dock, atIndex)` splices at that position. The overlay shows rectangular half-regions as visual feedback. `getDropZone(x, y, rect, titlebarHeight)` implements the diagonal math on normalized body coordinates. Multi-level recursive splitting is supported. The `.dock-splitter` divider is draggable to resize panes (ratio clamped to [0.1, 0.9], double-click resets to 0.5).

**Ghost drag:** For standalone windows, Shift initiates ghost mode at 5px threshold — once activated, releasing Shift does NOT cancel. Ghost matches source size with correct offset. Dropping on valid target docks; empty space moves. Self-drop is a no-op. For tabs, dragging vertically past `TAB_UNDOCK_THRESHOLD` (30px) enters ghost mode automatically (no Shift needed); Shift still works as an immediate override. Horizontal tab drag stays in reorder mode (multi-tab leaves). Dragging a tab never moves the dock: a single-tab leaf's lone tab enters ghost mode immediately on plain drag; move the dock by its empty tab-bar area.

**Undocking:** Drag a tab vertically away from its tab bar (past 30px threshold) to undock into ghost mode. The ghost can then be dropped on another window to dock/tab, or on empty space to place as standalone. Retains pane dimensions at drop position.

**Dissolve logic:** `removeTabFromLeaf` handles cleanup. Empty leaf → `collapseLeaf` (sibling replaces parent split). Single leaf + single tab → `dissolveDock` (back to standalone window).

**Key functions:** `createDockContainer`, `destroyDockContainer`, `renderDockTree`, `buildDockNodeDOM`, `mergeWindowsIntoTabs`, `mergeWindowsAsSplit`, `dockWindowAsTab`, `dockWindowAsSplit`, `undockWindow`, `removeTabFromLeaf`, `collapseLeaf`, `dissolveDock`, `activateTab`, `renderTabBar`, `setupTabDragFromMousedown`, `setupSplitterDrag`, `detectDropTarget`, `findLeafAtPoint`, `getDropZone`, `showDropOverlay`, `hideDropOverlay`, `executeDock`, `toggleMaximizeDock`, `closeDock`, `getLayoutUnits`, `isWindowMinimized`

**Integration:** `focusWindow` brings the dock container to front and activates the tab; `closeWindow`, `minimizeWindow`, `restoreWindow`, `toggleMaximize`, `nudgeWindow` all delegate to the dock container when docked. Layout functions use `getLayoutUnits()` (standalone windows + dock containers); `scaleWindowsToArea` and `getSnapEdges` include docks. `updateWindowTitle`/`startInlineRename` update dock tab titles. Help/about/plugin-about windows are `dockable: false`. Dock `mousedown` maps `e.target` to its `.dock-leaf` and calls `focusWindow(leaf.activeTab)` so `activeWinId` stays correct in split layouts. `refreshAllTableWindows` closes SQL-dropped tables via `closeWindow` (clearing the modified flag first) so docked tabs tear down properly. `undockWindow` clears `maximized`/`prevBounds`; `dissolveDock` transfers the dock's maximized state instead. Dock resize handles and splitter drag call `closeAutoFilter()` on mousedown. Minimize acts on the whole dock container, not individual tabs (intentional — undock first).

### Empty state

`#empty-state` — a `<section>` (not a `<div>`, so `.subwindow` `div:nth-of-type` test selectors keep their indices) inside `#window-area`, shown when no windows are open. Buttons: **Open File…** (`app.openFile`) and **Try Example Data** (`app.loadExampleData()` — three embedded sample CSVs mirroring `example/*.csv`, loaded as in-memory `File` objects so it works under `file://`). Below the hint, `.empty-state-privacy` states the privacy guarantee (data never sent to any server; see Privacy Guarantee section). Toggled in `updateWindowsList()` (hidden while `windows.length > 0`), which runs on every window create/close/minimize/restore. Tests: `test/integration/empty-state.spec.js`

### Theme contrast conventions

Text targets WCAG 4.5:1: `--text-dim` #aaaacc (secondary text), `--text-disabled` #72729a (disabled menu/context items only — deliberately dimmer). `--danger` = filled backgrounds with white text; `--danger-text` #ff7799 = danger-colored *text* on dark backgrounds (console error status, unsaved asterisk) since `--danger` fails as text. `#console-status.error` adds a tinted background + bold. Placeholders: #8a8ab0 via global `::placeholder`. Faint affordances (filter funnel, sort outline, `badge-faint` dots) sit at 0.22–0.3 white alpha. `test/integration/column-badges.spec.js` asserts some exact computed colors — update tests and CSS together.

### Row identity

Each row's primary key is its `_rownum` property (1-based index). Renumbered on insert/delete. Not a real column — excluded from CSV export.

## Development

No build tools. Develop with `python3 -m http.server 8000` (then open http://localhost:8000), or just open `index.html` directly — all dependencies are bundled locally.

## Testing

Playwright-based test suite (Chromium only). Tests are organized into `test/unit/`, `test/integration/`, and `test/e2e/`.

```bash
# Run all tests (installs deps + browser if needed)
./run-tests.sh   # or: npm test

# Run a single test file
npx playwright test --config test/playwright.config.js test/integration/sql-queries.spec.js

# Run tests matching a grep pattern
npx playwright test --config test/playwright.config.js -g "filter"
```

The test server runs on port 8274 (auto-started by Playwright config). Tests use `?test=1` query param which sets `window._appReady` after init. Test helpers are in `test/helpers.js` — notably `openApp()`, `uploadFile()`, `executeSQL()`, `waitForWindow()`, and `getTableData()`.

Tests run fully parallel (`fullyParallel: true`, workers = cores−2) — every test must stay independent: open its own page via `openApp()` and never rely on state from another test. Set `PW_WORKERS=1` to debug serially. Full suite: ~1.5 min parallel vs ~10 min serial.

Fixtures live in `test/` (`sample1.csv`, `sample.xlsx`, `sample.zip`, …).

## PyPI Packaging

Published as `csvsql` on PyPI. The Python package in `csvsql/` serves static files via `cli.py`.

**IMPORTANT:** `csvsql/static/` contains copies of the root static files (`app.js`, `index.html`, `style.css`, `lib/`, `example/`). These are NOT auto-synced — whenever you modify any root static file, you MUST copy it to `csvsql/static/` as well, or the `csvsql`/`csvsqlw` command will serve stale files.

```bash
# Sync static files to PyPI package (run after ANY change to root static files)
cp app.js index.html style.css csvsql/static/ && cp lib/* csvsql/static/lib/ && cp -r example csvsql/static/

# Build and publish
rm -rf dist build *.egg-info && python3 -m build
python3 -m twine upload dist/*
```

Version is in `pyproject.toml`.

## Conventions

- All state lives in the `app` IIFE's closure (`windows`, `tables`, `nextWinId`, etc.)
- Public methods are returned from the IIFE and called from HTML onclick handlers or internally
- Test internals are exposed via `app._test` (only used by Playwright tests)
- Table and column names are sanitized to `[a-zA-Z0-9_]` for SQL compatibility
- SQL identifiers use bracket-quoting (`[tableName]`) to handle edge cases
- SQL syntax highlighting uses the overlay technique: a div with highlighted spans behind a transparent textarea/input. The lexer is `sqlTokenize(text)` — `{ type, start, end, text }` tokens (`ws`/`comment`/`string`/`bracket`/`number`/`keyword`/`word`/`op`; `end` exclusive; token texts concatenate back to the input). `sqlHighlightHTML()` is a thin renderer over the tokens. Setup: `setupSQLHighlight()` for the console, inline in `renderTableView()` for filter inputs. The lexer is shared by highlighting and autocompletion — extend `sqlTokenize`, not the renderer
- SQL autocompletion context: `sqlCompletionContext(text, caret, opts)` is pure (no DOM/app state); returns `null` (caret in string/comment/number) or `{ start, end, prefix, items: [{ label, insert, kind }] }` (`[start, end)` = replace range; kind `column`/`table`/`keyword`). `opts.schema` = `{ tableName: [colNames] }`; `opts.filterTable` ranks that table's columns first and drops bare table suggestions (subqueries still get tables after FROM). Detection is lexical, not grammatical, so unknown syntax degrades to broader suggestions: after FROM/JOIN/INTO/UPDATE/TABLE or comma-continued FROM lists → tables; `identifier.` → that table's columns (resolves FROM/JOIN aliases, case-insensitive); SELECT INTO target → nothing (new name); default → columns of statement-mentioned tables (statements split on `;`), then tables, then keywords. Inserts are bracket-quoted when not plain identifiers or when colliding with a keyword. Must never throw for any (text, caret) — fuzz-enforced in `test/unit/sql-completion.spec.js`
- Autocomplete dropdown: `attachAutocomplete(inputEl, getContext)` wires the shared dropdown; attached to `#sql-input` in `setupSQLHighlight()` and each `.filter-input` in `renderTableView()` (before the filter's Escape handler so an open dropdown consumes the first Escape). `getContext` calls `sqlCompletionContext` with a fresh `liveSQLSchema()` snapshot and is try/catch-wrapped (errors degrade to no suggestions). Singleton state: `_acState`, `_acEl` (lazy `#sql-autocomplete` on `document.body`), `_acAccepting`. Keyboard contract: CLOSED intercepts nothing except Ctrl/Cmd+Space (explicit open); OPEN — Up/Down navigate, Tab/Enter accept, Escape closes (all `stopImmediatePropagation`), Ctrl/Cmd+Enter closes WITHOUT accepting and falls through to execution. Accept uses `setRangeText` (keeps native undo) + a bubbling `input` event. Opens on identifier char, `.`, `[`, or Ctrl+Space; closes on blur/outside mousedown/resize; caret position via `acCaretViewportPos()` (mirror div). Key functions: `attachAutocomplete`, `tryOpenAutocomplete`, `closeAutocomplete`, `acceptAutocomplete`, `renderAutocomplete`, `positionAutocomplete`, `liveSQLSchema`. Tests: `test/integration/autocomplete.spec.js`
- Query result tables are registered in SQLite via `registerTable()` so they can be queried and filtered like any other table
- `db.export()` in sql.js destroys custom functions — `registerDBFunctions()` re-registers them after each export
- SELECT INTO is intercepted and handled manually (SQLite doesn't support it natively)
- AI analysis (experimental) uses a SQL tool-use loop: the AI writes SQL in ```sql code blocks, which are executed against SQLite and results fed back (up to 5 rounds). AI can also be used without any tables loaded (general chat mode)
- AI rich output: ```chart (Chart.js config JSON), ```table (columns/rows JSON), ```pdf (document spec JSON) blocks are post-processed into inline charts, HTML tables, and PDF download links. Chart.js and jsPDF are lazy-loaded via CDN on first use. PDFs support text, heading, table, chart, and image content blocks
- AI images: users can drag-and-drop PNG/JPG images onto the AI chat area. Stored in `_aiImages` (name → data URL). Available for inclusion in PDF reports via `{"type":"image","name":"filename.png"}`. Image drop on AI panel is intercepted before the global file-open drop handler
- AI providers: WebLLM (default, in-browser via WebGPU), Ollama (local), Claude (cloud), OpenAI (cloud), Gemini (cloud), Grok (cloud). OpenAI, Gemini, and Grok share `generateOpenAICompat()` (OpenAI-compatible chat-completions streaming; only endpoint URL and key differ). Retired saved model IDs are migrated on load (`_retiredModels` map)
- AI settings (provider, model, API keys) are persisted in localStorage under `csvsql_ai_settings`
- AI unlock: the AI console tab (`#console-tab-ai`, `display:none` in index.html) is hidden unless Shift is held while the page loads; pressing Shift after load must do nothing. `_aiUnlocked` (module state, NOT persisted — per-session only) is set by `setupAIUnlockDetection()`. Two detection paths. **Reload path (deterministic):** the outgoing page tracks live Shift state (`shiftDown`, from the `shiftKey` flag of every input event, reset on blur) and on `pagehide` writes a one-shot `sessionStorage` flag (`csvsql_ai_unlock`) if Shift is down; the incoming page consumes it at setup — this makes Ctrl/Cmd+Shift+R reliable regardless of key-release order. **Event path (first navigations):** the browser cannot poll keyboard state, so unlock requires an input event with `shiftKey` set (hold Shift and move the mouse). Before window `load`, any such event unlocks; after load it still unlocks except Shift's own `keydown`. Shift-less events from *other* keys are ignored (a reload combo can't kill detection); Shift's own `keydown`/`keyup` or a shift-less pointer event ends detection without unlocking. `unlockAI()` reveals the tab and rewrites `.empty-state-privacy` to the AI-aware wording (the default HTML wording mentions no AI — keep both variants in sync with the privacy guarantee). While locked: `switchConsoleTab('ai')` and `runAI()` early-return (no Ollama probe from `detectAIProvider`), and AI image drag/drop is ignored. Test hooks: `app._test.unlockAI`, `app._test.aiUnlocked`. Tests: `test/integration/ai-unlock.spec.js`
- AI conversation history (`_aiConversation` array) and prompt history (Up/Down arrow) are in-memory only; conversation clears with the console
- SQL query history: `_sqlHistory` persisted in localStorage under `csvsql_sql_history` (cap `MAX_HISTORY` = 100, deduped via shared `pushHistory`; stores the raw query as typed, pre-`autoQuoteSQL`). Up/Down recall uses the shared `handleHistoryKey` (cursor must be at very start/end), wired in the `#sql-input` keydown handler in `setupKeyboard`, skipped while the autocomplete dropdown is open (`_acState.inputEl` check). Programmatic value changes refresh the highlight overlay via `_syncSQLHighlight` (module-level hook assigned in `setupSQLHighlight`). Tests: `test/integration/sql-history.spec.js`
- Console tab switching auto-focuses that tab's input (SQL or AI prompt)
- Help windows (Manual, About) are singletons — `showHelpWindow(title, bodyHTML, asDialog)` focuses/restores existing window instead of creating a duplicate. `asDialog: true` creates a dialog-style subwindow (no min/max/resize/statusbar) — used for the short, fixed-content About CSVSQL window; the Manual and Plugin Expression Reference stay resizable
- Cell selection is a rectangle defined by `win.anchorCell` (fixed corner) and the focused cell (lead), cached as a Set of `"rownum:colName"` keys in `win.selectedCells` — keys use column *names* + `_rownum` so selection survives sort, filter, reorder, and rename. `applyCellHighlights()` rebuilds `.row-highlight`/`.col-highlight`/`.cell-selected` (and find-match) classes from this Set after every `renderVisibleRows()` (virtual scrolling). Anchor resets on user focusin; programmatic focus sets `win._programmaticFocus` to skip the reset. Helpers: `selectAllCells` (sets `_copyWithHeader`), `selectNoneCells` (clears selection, anchor, `_copyWithHeader`, `selectedCol`), `isAllSelected`, `selectRows(win, fromDi, toDi)`, `selectColumns(win, fromColIdx, toColIdx)`. Clicking a column header calls `selectColumns` (Shift+click extends) and sets `win.selectedCol` for Ctrl+Arrow reorder; `selectedCol` is cleared by cell focusin, `selectRows`, `selectAllCells`, `selectNoneCells` — NOT set by sort-badge or filter-button clicks. `#` corner cell click toggles select-all/none; `td.row-num` click selects rows (drag/Shift+click for ranges). `_copyWithHeader` clears on normal cell focusin
- Clipboard: `copySelectedCells(win)` reads values from `win.selectedCells`, builds TSV (tab-separated columns, newline-separated rows), and writes to `navigator.clipboard`. For each cell, if a plugin display transform is active and enabled (column not in `win.disabledTransforms`), the formatted value from `getDisplayValue()` is used; otherwise the raw value is used. When `win._copyWithHeader` is true, the column header row is prepended. `cutSelectedCells(win)` copies then clears selected cells (undoable). `pasteAtAnchor(win)` reads TSV from clipboard and fills right and down from `win.anchorCell`, clipping to table bounds. Copy and cut are handled in both the per-table keydown handler (when a data cell has focus) and the global `document` keydown handler (when focus is elsewhere, e.g. column header or titlebar) — edit mode passes through to native browser behavior. Copy, cut, and paste each show a `showToast` confirmation with cell counts (`describeCellCount`); cut copies silently via `copySelectedCells(win, { silent: true })`; clipboard failures show error toasts. After paste/cut/undo/redo re-render the table, `refocusAnchorCell(win)` re-focuses the anchor cell's new DOM node (with `preventScroll`) so the per-table keydown handler continues to receive events without disturbing the scroll position
- Undo/redo stacks (`t._undoStack`, `t._redoStack`) live on the table object, lazily initialized. Cell-level entries: `{ type: 'edit'|'paste'|'cut'|'replace', changes: [{ rownum, col, oldValue, newValue }] }`. Structural entries carry `rowUndo` (`insertRow`/`deleteRow`) or `columnUndo` (`insertColumn`/`deleteColumn`/`renameColumn`/`reorderColumn`/`resizeColumn` — resize pushed by `pushResizeUndo()` from drag and double-click auto-fit). Cell-level undo syncs via `debouncedSync`; structural undo uses `registerTable` (column ops) or `syncToSQL` (row ops) + `rebuildTable`. `undoTable(tableName, win)` pops undo → dispatches to `undoStructural` or restores cell values → pushes redo; `redoTable` is the reverse; new edits clear redo. Redo is bound to Ctrl/Cmd+Shift+Z AND Ctrl/Cmd+Y. Both show toasts (`undoActionSummary`; shared `undoActionLabel` also feeds the Edit menu's contextual labels, grayed out when stacks are empty)
- Cell editability is a two-state model. Data cells render as `<td class="data-cell" tabindex="0">` — focusable for selection but **not** editable. `enterEditMode(td)` sets `contenteditable="true"`, places the caret at the end, and scrolls the cell to show the caret (`td.scrollLeft = td.scrollWidth`); `exitEditMode(td)` removes the attribute and resets `td.scrollLeft = 0`. In edit mode, CSS enables cell-internal scrolling (hidden scrollbar) to keep the cursor visible. `i`, F2, Ctrl/Cmd+U, Ctrl/Cmd+click, mouse double-click (delegated `dblclick` listener on `table`), and touch double-tap are the entry points. The blur handler saves + exits edit mode; Escape either reverts the edit (in edit mode) or clears selection (in select mode). Keep the `data-cell` class as the identity check — don't rely on the presence of `contenteditable` to identify data cells
- Arrow-key behavior on a data cell: select mode — plain arrow collapses to adjacent cell (`moveSingleCellSelection`), Shift+arrow extends (`extendCellSelection`), Ctrl/Cmd+←/→ moves the header-selected column (`moveSelectionColumns`, only when `win.selectedCol` set). Edit mode — Up/Down commits and moves; Left/Right pass through to the native caret. Vim h/j/k/l remap to arrows (select mode only, no modifiers) through the same `navKey` path; Shift+H/J/K/L extends. Ctrl/Cmd+H/J/K/L = `nudgeWindow` (5 px), Ctrl/Cmd+Shift+L/H = `cycleTableWindow` — both bypass the vim remap. Tab/Shift+Tab move left/right in both modes. Enter moves down; in edit mode it commits and returns to the `_editStartColIdx` column
- Context menus (`showRowContextMenu`, `showColumnContextMenu`, `showCornerContextMenu`, one delegated `contextmenu` listener on `table`): row number → Insert Row Below / Delete Row; column header (selects the column + sets `selectedCol` first) → Insert Column Right / Delete Column / Manage Columns…; `#` corner cell → insert row/column at position 0 (key entry point for empty tables). `deleteColumn` cleans up `columnFilters`, `sortCols`, `selectedCol`, `colWidths`, `selectedCells`, `anchorCell`, `linkFilters`, `disabledTransforms` on ALL windows, then `registerTable` + `rebuildTable`; disabled at 1 remaining column. `insertColumn(tableName, colName, atIndex)` splices `t.columns` + a 100px width into `colWidths`; `insertRow` splices `t.rows`. All push undo entries. Insert column and `startColumnRename` both validate duplicate names (dialog error / red border on the inline input)
- Column reorder: plain drag on a header reorders (5 px threshold); Ctrl/Cmd+click renames; clicking a header selects the column via `selectColumns` and sets `win.selectedCol`. Sorting is triggered by clicking the sort button (`.col-sort-btn`, which wraps `.col-badge-sort`) inside `.th-inner`, not by the header click. Ctrl/Cmd+←/→ moves the header-selected column (`win.selectedCol`) from both the global keyboard handler and the per-table `moveSelectionColumns` handler. All paths funnel through `reorderColumn(win, fromIdx, toIdx)`, which splices `tables[name].columns`, re-registers the SQLite table, and calls `rebuildTable(win)`
- Column Manager: dialog subwindow for bulk column reorder (Edit menu, Ctrl/Cmd+Shift+M, or header context menu). Singleton `_activeColManagerWin`. Searchable list, multi-select (click/Shift/Ctrl), drag to reorder or drop onto table headers, Alt+Up/Down moves, double-click scrolls the table to the column. Internal reorders mutate `t.columns`/`tw.colWidths` directly (no per-move undo); `finalizeColManager(winId)` pushes ONE batched `reorderColumn` undo on close by diffing against the open-time snapshot. Other windows dim via `applyColManagerDimming`/`clearColManagerDimming` (`.col-manager-dimmed`). Global Esc (before the Ctrl/Meta gate in `setupKeyboard`) closes it unless focus is in an unrelated input. Dialog subwindows (`opts.dialog`) omit min/max buttons and status bar but ARE resizable and draggable; they're excluded from edge snapping (`snapPosition` early-returns for `isDialog`, `getSnapEdges` skips them) and from `getLayoutUnits()` so layouts don't move them. Non-modal dialogs stay on top — `raiseDialogs()` (called from `focusWindow`, `layoutCascade`, dock mousedown) re-raises `isDialog && !backdropEl` windows. Key functions: `showColManager`, `closeColManager`, `finalizeColManager`

- Find & Replace: `showFindReplace(targetWinId)` opens a non-modal dialog subwindow (singleton `_activeFindWin`, mirrors the Column Manager pattern) targeting one data window; Ctrl/Cmd+F (works with a data cell focused, not from other inputs) or Edit menu `#btn-find`. Match state lives on the *target* window — `win._findMatches` (Set of `"rownum:col"` keys) + `win._findCurrentKey` — rendered as `.cell-find-match`/`.cell-find-current` by `applyCellHighlights` (survives virtual scrolling). Search runs over `win._displayRows` × `win._columns` (respects filter/sort) against raw values; options: match case, entire cell. Navigation uses `scrollCellIntoView(win, di, ci, {smooth:true})` (scrolls without focusing).
