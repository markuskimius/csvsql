# CLAUDE.md

## What This Is

CSVSQL is a browser-based CSV database: CSV files become SQL-queryable tables with editable cells in a multi-window interface. No build step or server required — open `index.html` directly in a browser. Also distributed via PyPI (`pip install csvsql`). The hosted instance at https://app.cbreak.org/csvsql/ is the primary usage path (pip = optional standalone); documented in README and the manual Overview — keep in sync.

## Privacy Guarantee (hard constraint)

The app MUST NEVER send user data to any server or website. No telemetry, no analytics, no CDN loads at runtime (all dependencies are bundled in `lib/`), no background network requests of any kind. The only permitted network activity is explicitly user-initiated: (1) **File → Open URL** fetches the URL the user typed; (2) the AI assistant — which is **hidden by default** and only revealed by holding Shift while the page loads (see AI unlock in Conventions) — contacts Ollama (local) or a cloud provider (Claude, OpenAI, Gemini, or Grok) only when the user has configured that provider with their own API key. While AI is hidden, the app must make no AI-related network activity at all (not even the Ollama localhost probe in `detectAIProvider`). Never add a feature that violates this, and this promise is stated on the empty-state welcome screen, in the in-app manual (Privacy section), and in README.md — keep all three in sync if the network behavior ever changes. The AI feature is deliberately **undocumented** in README.md and the in-app manual (owner's decision): their privacy statements mention only Open URL, with no AI reference; only the unlocked welcome-message variant and this file mention AI. Don't re-add AI documentation to README or the manual.

## Architecture

Single-page app with three core files:

- **index.html** — Shell: menubar, workspace area (with `#empty-state` welcome screen), SQL console panel (default height 113px = 3 lines of SQL text; drag handle clamps 60px–50vh; `#console-actions` buttons equal-width — grid `1fr` + nowrap, like `.empty-state-actions`), hidden file input, script tags. `updateMenuState()` runs at menu-open time: Save/Save As enabled only for table windows (`!!t` — Manual/About/Expression Reference don't count), Close Window for any window (`!!activeWinId`), layout buttons via `hasAny`
- **style.css** — Dark theme styling, window management visuals, table layout
- **app.js** — All application logic in a single IIFE (`app` module), exposing methods on the global `app` object

### Key dependencies (bundled in `lib/`, per the privacy guarantee)

- **Papa Parse** — CSV parsing/unparsing
- **sql.js** — SQLite compiled to WebAssembly; each opened CSV is registered as a SQLite table
- **SheetJS (XLSX)** — Excel file reading/writing
- **JSZip** — ZIP archive support
- **Chart.js** — Inline chart rendering (lazy-loaded on first AI chart)
- **jsPDF + autotable** — PDF report generation (lazy-loaded on first AI PDF)
- **@mlc-ai/web-llm** — In-browser LLM inference via WebGPU (lazy-loaded)

All bundled libraries are credited in `THIRD-PARTY-NOTICES.md` (root + synced `csvsql/static/` copy; in `license-files` in `pyproject.toml`) — update it when adding/upgrading a library. README and the About dialog deliberately name only Papa Parse, sql.js, SheetJS, and JSZip: the AI-only deps (web-llm, Chart.js, jsPDF) stay out of user-facing docs per the AI-undocumented rule; the notices file lists everything.

### Data flow

Open: Papa Parse → `tables[name]` (columns, rows, filename, modified flag) → registered in SQLite (`CREATE TABLE` + prepared batch INSERTs). Cell edits update `tables[name].rows` and sync back via `syncToSQL()`. Query results become new `tables` entries in new subwindows. Save: Papa.unparse → browser download.

### Window management

Custom subwindow system — each table/query result gets a draggable, resizable, minimizable window inside `#window-area`; drag, resize, and keyboard nudge clamp to its bounds. Mouse interactions require the left button (`e.button !== 0` guard); right/middle click on data cells calls `e.preventDefault()`. Drag/resize snaps to workspace and other window edges within `SNAP_THRESHOLD` (10 px) with blue guide lines — helpers: `getSnapEdges`, `findSnap`, `snapPosition`, `showSnapGuides`/`hideSnapGuides`. Dragging the titlebar of a maximized window (or the tab bar of a maximized dock) restores its `prevBounds` via `unmaximizeForDrag()` (grab point stays proportional; a click without movement does not unmaximize); resizing a maximized window/dock clears the `maximized` flag. Layout functions (tile, grid, cascade) reposition all visible windows; `scaleWindowsToArea()` rescales proportionally on browser/console resize. Each window tracks its own sort/filter state. The `windows` array and `tables` object are the central data structures.

### Tabbing and docking

Windows combine into dock containers: a `.dock-container` positioned in `#window-area` like a `.subwindow`, with its own resize handles, maximize/minimize, and a recursive binary split tree.

**Data model:** each entry in `dockContainers[]` has a `root` DockNode — either a leaf (tab group) or a split node. Split nodes: `direction` ('horizontal'|'vertical'), `ratio` (0.0–1.0), two children. Leaf nodes: `tabs` (window IDs), `activeTab`, and DOM refs (`el`, `tabBarEl`, `contentEl`). Window objects gain `dockId` (null or dock ID), `dockLeaf` (containing leaf), and `dockable` (false for help/about windows).

**Tabbing:** Shift-drag a titlebar onto another window's titlebar to merge into a tab group (touch: long-press the titlebar, then drag — see Conventions). Tabs are content-width. Only 1 level of tabbing (no nested tab groups; each pane in a dock split can be its own tab group). Active tab's `.win-body`/`.win-statusbar` visible; inactive tabs' content hides via `display: none` with `dataset.winId`. Double-clicking a tab toggles maximize/restore on the dock. Single-tab leaves inside a split hide their tab bar (`single-tab`); it reappears with a second tab. Tabs reorder by dragging left/right within the tab bar (no Shift) — dragged tab dims, blue indicator shows the drop position. A `::after` pseudo-element gives the tab bar a 40px min grab area right of the tabs so the dock stays draggable.

**Docking:** Shift-drop a window onto another window's body to create a split dock (touch: same long-press path); without Shift, dragging just moves. Drop zones: the body (below titlebar/tab-bar) splits into 4 triangular zones by its diagonals (top/right/bottom/left). Dropping on the titlebar/tab bar triggers tabbing (center zone) with position-aware insertion — `detectDropTarget` computes `tabIndex` from cursor X vs tab midpoints, `showDropOverlay` renders a `.dock-drop-tab-indicator` line, `dockWindowAsTab(winId, leaf, dock, atIndex)` splices there. `getDropZone(x, y, rect, titlebarHeight)` implements the diagonal math. Splits nest recursively. The `.dock-splitter` divider resizes panes (ratio clamped [0.1, 0.9], double-click resets to 0.5).

**Ghost drag:** Standalone windows: Shift initiates ghost mode at 5px threshold — once active, releasing Shift does NOT cancel. Ghost matches source size/offset; drop on a valid target docks, empty space moves; self-drop is a no-op. Tabs: dragging vertically past `TAB_UNDOCK_THRESHOLD` (30px) enters ghost mode automatically (Shift = immediate override); horizontal drag stays in reorder mode (multi-tab leaves). Dragging a tab never moves the dock — a single-tab leaf's lone tab ghosts immediately on plain drag; move the dock by its empty tab-bar area. An undocked ghost dropped on empty space becomes standalone, retaining pane dimensions.

**Dissolve logic:** `removeTabFromLeaf` handles cleanup. Empty leaf → `collapseLeaf` (sibling replaces parent split). Single leaf + single tab → `dissolveDock` (back to standalone). Same-dock moves pass `skipCleanup`, deferring to `cleanupAfterTabRemoval` after re-docking — it must `activateTab` (not just `renderTabBar`) so the source leaf's remaining tab body is unhidden.

**Integration:** `focusWindow` brings the dock to front and activates the tab; `closeWindow`/`minimizeWindow`/`restoreWindow`/`toggleMaximize`/`nudgeWindow` delegate to the dock when docked. Layout functions use `getLayoutUnits()` (standalone windows + docks); `scaleWindowsToArea`/`getSnapEdges` include docks. `updateWindowTitle`/`startInlineRename` update tab titles. Help/about/plugin-about windows are `dockable: false`. Dock `mousedown` maps `e.target` to its `.dock-leaf` and calls `focusWindow(leaf.activeTab)` so `activeWinId` stays correct in splits. `refreshAllTableWindows` closes SQL-dropped tables via `closeWindow` (clearing the modified flag first). `undockWindow` clears `maximized`/`prevBounds`; `dissolveDock` transfers the dock's maximized state. Dock resize handles and splitter drag call `closeAutoFilter()` on mousedown. Minimize acts on the whole dock, not individual tabs (intentional — undock first).

### Empty state

`#empty-state` — a `<section>` (not a `<div>`, so `.subwindow` `div:nth-of-type` test selectors keep their indices) inside `#window-area`, shown when no windows are open. Buttons: **Open File…** (`app.openFile`) and **Try Example Data** (`app.loadExampleData()` — embedded sample CSVs mirroring `example/*.csv`, works under `file://`). `.empty-state-privacy` states the privacy guarantee. Toggled in `updateWindowsList()`. Tests: `test/integration/empty-state.spec.js`

### Scrollbars

Global-only styling (`::-webkit-scrollbar`: 12px gutter, 6px thumb centered by 3px transparent border + `background-clip: padding-box`; coarse 16px/8px). Resize handles' 3px inward overhang must stay equal to the thumb's transparent border. Per-element rules only to hide (`.dock-tab-bar`, edit-mode cells).

### Theme contrast conventions

Text targets WCAG 4.5:1: `--text-dim` #aaaacc (secondary text), `--text-disabled` #72729a (disabled menu/context items only — deliberately dimmer). `--danger` = filled backgrounds with white text; `--danger-text` #ff7799 = danger-colored *text* on dark backgrounds (console error status, unsaved asterisk) since `--danger` fails as text. `#console-status.error` adds a tinted background + bold. Placeholders: #8a8ab0 via global `::placeholder`. Faint affordances (filter funnel, sort outline, `badge-faint` dots) sit at 0.22–0.3 white alpha. `test/integration/column-badges.spec.js` asserts some exact computed colors — update tests and CSS together.

### Row identity

A row's primary key is its `_rownum` (1-based; renumbered on insert/delete). Not a real column — excluded from CSV export.

## Testing

Playwright test suite (Chromium only): `test/unit/`, `test/integration/`, `test/e2e/`.

```bash
./run-tests.sh   # all tests (or: npm test)
npx playwright test --config test/playwright.config.js test/integration/sql-queries.spec.js   # one file
```

Test server: port 8274 (auto-started). Tests use `?test=1`, which sets `window._appReady` after init. Test helpers are in `test/helpers.js` — notably `openApp()`, `uploadFile()`, `executeSQL()`, `waitForWindow()`, and `getTableData()`.

Tests run fully parallel (`fullyParallel: true`, workers = cores−2) — every test must stay independent: open its own page via `openApp()` and never rely on state from another test. Set `PW_WORKERS=1` to debug serially.

Fixtures (`sample1.csv`, `sample.xlsx`, …) live in `test/`.

## PyPI Packaging

The Python package in `csvsql/` serves static files via `cli.py`.

**IMPORTANT:** `csvsql/static/` contains copies of the root static files (`app.js`, `index.html`, `style.css`, `THIRD-PARTY-NOTICES.md`, `lib/`, `example/`). These are NOT auto-synced — whenever you modify any root static file, you MUST copy it to `csvsql/static/` as well or the `csvsql` command will serve stale files.

```bash
# Sync static files, then build and publish
cp app.js index.html style.css THIRD-PARTY-NOTICES.md csvsql/static/ && cp lib/* csvsql/static/lib/ && cp -r example csvsql/static/
rm -rf dist build *.egg-info && python3 -m build
python3 -m twine upload dist/*
```

Version is in `pyproject.toml`.

## Conventions

- All state lives in the `app` IIFE's closure (`windows`, `tables`, `nextWinId`, etc.)
- Public methods are returned from the IIFE and called from HTML onclick handlers or internally
- Test internals are exposed via `app._test`
- Table/column names are sanitized to `[a-zA-Z0-9_]`; SQL identifiers use bracket-quoting (`[tableName]`) for edge cases
- SQL syntax highlighting uses the overlay technique: a div with highlighted spans behind a transparent textarea/input. Lexer `sqlTokenize(text)` → `{ type, start, end, text }` tokens (`ws`/`comment`/`string`/`bracket`/`number`/`keyword`/`word`/`op`; `end` exclusive; token texts concatenate back to the input); `sqlHighlightHTML()` is a thin renderer. Setup: `setupSQLHighlight()` (console), inline in `renderTableView()` (filter inputs). The lexer is shared with autocompletion — extend `sqlTokenize`, not the renderer
- SQL autocompletion context: `sqlCompletionContext(text, caret, opts)` is pure (no DOM/app state); returns `null` (caret in string/comment/number) or `{ start, end, prefix, items: [{ label, insert, kind }] }` (`[start, end)` = replace range; kind `column`/`table`/`keyword`). `opts.schema` = `{ tableName: [colNames] }`; `opts.filterTable` ranks that table's columns first and drops bare table suggestions. Detection is lexical — unknown syntax degrades to broader suggestions: after FROM/JOIN/INTO/UPDATE/TABLE or comma-continued FROM lists → tables; `identifier.` → that table's columns (resolves aliases, case-insensitive); SELECT INTO target → nothing; default → columns of statement-mentioned tables (split on `;`), then tables, then keywords. Keywords are context-gated via `_sqlKeywordRules` (ctx `{ stmtStart, openParen, filterTable, anchorKw }`; extend with a words-set + predicate; rules only narrow): type names only after `CAST(… AS`, NOCASE only after COLLATE (both out of the default pool), `_sqlStmtOnly` commands only at statement start/after EXPLAIN and never in filter inputs, SELECT/WITH also inside an open paren or after UNION/EXCEPT/INTERSECT/ALL/AS. Inserts bracket-quoted when not plain identifiers or colliding with a keyword. Must never throw for any (text, caret) — fuzz-enforced in `test/unit/sql-completion.spec.js`
- Autocomplete dropdown: `attachAutocomplete(inputEl, getContext)` wires the shared dropdown; attached to `#sql-input` in `setupSQLHighlight()` and each `.filter-input` in `renderTableView()` (before the filter's Escape handler so an open dropdown consumes the first Escape). `getContext` calls `sqlCompletionContext` with a fresh `liveSQLSchema()` snapshot, try/catch-wrapped (errors → no suggestions). Singleton state: `_acState`, `_acEl` (lazy `#sql-autocomplete`), `_acAccepting`. Keyboard: CLOSED intercepts nothing except Ctrl/Cmd+Space; OPEN — Up/Down navigate, Tab/Enter accept, Escape closes (all `stopImmediatePropagation`), Ctrl/Cmd+Enter closes WITHOUT accepting and falls through to execution. Accept uses `setRangeText` (keeps native undo) + a bubbling `input` event. Opens on identifier char, `.`, `[`, Ctrl+Space; closes on blur/outside mousedown/resize; caret position via `acCaretViewportPos()` (mirror div). Tests: `test/integration/autocomplete.spec.js`
- Query results are registered via `registerTable()` so they're queryable/filterable like any table
- `db.export()` in sql.js destroys custom functions — `registerDBFunctions()` re-registers them after each export
- SELECT INTO is intercepted and handled manually (unsupported by SQLite)
- AI analysis (experimental) uses a SQL tool-use loop: the AI writes SQL in ```sql code blocks, which are executed against SQLite and results fed back (up to 5 rounds); works with no tables loaded (general chat mode)
- AI rich output: ```chart (Chart.js config JSON), ```table (columns/rows JSON), ```pdf (document spec JSON) blocks are post-processed into inline charts, HTML tables, and PDF download links (Chart.js/jsPDF lazy-loaded from `lib/` on first use). PDFs support text, heading, table, chart, and image blocks
- AI images: drag-and-drop PNG/JPG onto the AI chat area; stored in `_aiImages` (name → data URL); usable in PDF reports via `{"type":"image","name":"filename.png"}`. Drop is intercepted before the global file-open handler
- AI providers: WebLLM (default, in-browser via WebGPU), Ollama (local), and cloud: Claude, OpenAI, Gemini, Grok — the latter three share `generateOpenAICompat()` (OpenAI-compatible streaming; only endpoint URL and key differ). Retired saved model IDs migrate on load (`_retiredModels`)
- AI settings (provider, model, API keys) are persisted in localStorage under `csvsql_ai_settings`
- AI unlock: the AI console tab (`#console-tab-ai`, `display:none` in index.html) is hidden unless Shift is held while the page loads; pressing Shift after load must do nothing. `_aiUnlocked` (module state, NOT persisted) is set by `setupAIUnlockDetection()`. Two paths: **reload** — the outgoing page tracks live Shift state (`shiftDown`, reset on blur) and on `pagehide` writes a one-shot `sessionStorage` flag (`csvsql_ai_unlock`) consumed at next setup (makes Ctrl/Cmd+Shift+R reliable regardless of key-release order); **event path** — an input event with `shiftKey` set unlocks (any before window `load`; after load, all except Shift's own `keydown`); Shift's own `keydown`/`keyup` or a shift-less pointer event ends detection without unlocking. `unlockAI()` reveals the tab and rewrites `.empty-state-privacy` to the AI-aware wording (default HTML mentions no AI — keep both in sync with the privacy guarantee). While locked: `switchConsoleTab('ai')` and `runAI()` early-return (no Ollama probe from `detectAIProvider`); AI image drag/drop ignored. Test hooks: `app._test.unlockAI`/`aiUnlocked`. Tests: `test/integration/ai-unlock.spec.js`
- AI conversation history (`_aiConversation` array) and prompt history (Up/Down arrow) are in-memory only; conversation clears with the console
- SQL query history: `_sqlHistory` in localStorage `csvsql_sql_history` (cap `MAX_HISTORY` = 100, deduped via shared `pushHistory`; stores the raw query pre-`autoQuoteSQL`). Up/Down recall via shared `handleHistoryKey` (cursor at very start/end), wired in the `#sql-input` keydown in `setupKeyboard`, skipped while the dropdown is open (`_acState.inputEl`). Programmatic value changes refresh the overlay via `_syncSQLHighlight` (hook assigned in `setupSQLHighlight`). History panel: `#btn-sql-history` (after Run, which must stay `:first-child` in `#console-actions` for the `executeSQL` helper; hidden on the AI tab) toggles `#sql-history-panel` (singleton `_historyPanel`). Newest-first, highlighted; row click → `loadHistoryEntry` (copy into input for editing), ▶ → `executeQuery()` (passes `{focus:false}` on coarse pointers — executing must not pop the soft keyboard), Clear History wipes history + localStorage. Closes on Escape/outside mousedown/tab switch; resize/`visualViewport` events reposition via `positionSQLHistory()` (viewport-clamped for soft keyboards — don't revert to close-on-resize); coarse-pointer CSS enlarges rows. Tests: `test/integration/sql-history.spec.js`
- Console tab switching auto-focuses that tab's input (SQL or AI prompt)
- Help windows (Manual, About) are singletons — `showHelpWindow(title, bodyHTML, asDialog)` focuses/restores existing window instead of creating a duplicate. `asDialog: true` creates a dialog-style subwindow (no min/max/resize/statusbar) — used for the short, fixed-content About CSVSQL window; the Manual and Plugin Expression Reference stay resizable
- Cell selection is a rectangle defined by `win.anchorCell` (fixed corner) and the focused cell (lead), cached as a Set of `"rownum:colName"` keys in `win.selectedCells` — keys use column *names* + `_rownum` so selection survives sort, filter, reorder, and rename. `applyCellHighlights()` rebuilds highlight/find-match classes from this Set after every `renderVisibleRows()`. Anchor resets on user focusin; programmatic focus sets `win._programmaticFocus` to skip the reset. Helpers: `selectAllCells` (sets `_copyWithHeader`), `selectNoneCells` (clears selection, anchor, `_copyWithHeader`, `selectedCol`), `isAllSelected`, `selectRows(win, fromDi, toDi)`, `selectColumns(win, fromColIdx, toColIdx)`. Header click calls `selectColumns` (Shift+click extends) and sets `win.selectedCol` for Ctrl+Arrow reorder; `selectedCol` cleared by cell focusin, `selectRows`, `selectAllCells`, `selectNoneCells` — NOT set by sort/filter-button clicks. `#` corner click toggles select-all/none; `td.row-num` click selects rows (drag/Shift+click for ranges). `_copyWithHeader` clears on normal cell focusin
- Clipboard: `copySelectedCells(win)` builds TSV from `win.selectedCells` → `navigator.clipboard`, using `getDisplayValue()` when a transform is active and enabled, else raw; `win._copyWithHeader` prepends the header row. `cutSelectedCells(win)` copies then clears (undoable). `pasteAtAnchor(win)` fills right/down from `win.anchorCell`, clipping to bounds. Copy/cut are handled in both the per-table keydown (data cell focused) and global `document` keydown (focus elsewhere) — edit mode passes through to native behavior. Each shows a `showToast` with cell counts (`describeCellCount`); cut copies silently (`{ silent: true }`); clipboard failures show error toasts. After paste/cut/undo/redo re-render, `refocusAnchorCell(win)` re-focuses the anchor cell's new DOM node (with `preventScroll`) so the per-table keydown keeps receiving events without disturbing scroll
- Undo/redo stacks (`t._undoStack`/`t._redoStack`) live on the table object, lazily initialized. Cell-level entries: `{ type: 'edit'|'paste'|'cut'|'replace', changes: [{ rownum, col, oldValue, newValue }] }`. Structural entries carry `rowUndo` (`insertRow`/`deleteRow`) or `columnUndo` (`insertColumn`/`deleteColumn`/`renameColumn`/`reorderColumn`/`resizeColumn` — resize via `pushResizeUndo()`). Cell-level undo syncs via `debouncedSync`; structural uses `registerTable` (column ops) or `syncToSQL` (row ops) + `rebuildTable`. `undoTable(tableName, win)` pops undo → `undoStructural` or cell restore → pushes redo; `redoTable` is the reverse; new edits clear redo. Redo = Ctrl/Cmd+Shift+Z AND Ctrl/Cmd+Y. Both toast (`undoActionSummary`; shared `undoActionLabel` also feeds the Edit menu's contextual labels)
- Cell editability is a two-state model. Data cells render as `<td class="data-cell" tabindex="0">` — focusable for selection, **not** editable. `enterEditMode(td)` sets `contenteditable="true"`, caret at end, scrolls the cell to show it (`td.scrollLeft = td.scrollWidth`); `exitEditMode(td)` removes the attribute, resets scroll. Edit-mode CSS enables cell-internal scrolling (hidden scrollbar). Entry points: `i`, F2, Ctrl/Cmd+U, Ctrl/Cmd+click, double-click (delegated on `table`), touch double-tap. Blur saves + exits; Escape reverts the edit (edit mode) or clears selection (select mode). Keep the `data-cell` class as the identity check — don't rely on `contenteditable` presence
- Arrow keys on a data cell: select mode — arrow collapses to adjacent cell (`moveSingleCellSelection`), Shift+arrow extends (`extendCellSelection`), Ctrl/Cmd+←/→ moves the header-selected column (`moveSelectionColumns`, needs `win.selectedCol`). Edit mode — Up/Down commits and moves; Left/Right go to the native caret. Vim h/j/k/l remap to arrows (select mode, no modifiers) via `navKey`; Shift+H/J/K/L extends; Ctrl/Cmd+H/J/K/L = `nudgeWindow` (5 px), Ctrl/Cmd+Shift+L/H = `cycleTableWindow` (both bypass the remap). Tab/Shift+Tab move left/right in both modes. Enter moves down; in edit mode it commits and returns to the `_editStartColIdx` column
- Context menus (`showRowContextMenu`, `showColumnContextMenu`, `showCornerContextMenu`, one delegated `contextmenu` listener on `table`; long-press is the touch path): row number → Insert Row Below / Delete Row; column header (selects it first) → Rename Column… / Sort Asc / Sort Desc / Add to Multi-sort (unsorted col while other sorts exist) / Remove from Sort (sorted col) / Insert Column Right / Delete Column / Manage Columns…; `#` corner → insert row/column at 0 (key entry point for empty tables) / Rename Table… (`startInlineRename`; also Edit-menu `#btn-rename-table`). Sort paths share `toggleColumnSort(win, col, additive)` (button) / `setColumnSort(win, col, dir, additive)` (menu). `deleteColumn` cleans up `columnFilters`, `sortCols`, `selectedCol`, `colWidths`, `selectedCells`, `anchorCell`, `linkFilters`, `disabledTransforms` on ALL windows, then `registerTable` + `rebuildTable`; disabled at 1 remaining column. `insertColumn(tableName, colName, atIndex)` splices `t.columns` + a 100px width into `colWidths`; `insertRow` splices `t.rows`. All push undo entries. Insert column and `startColumnRename` both validate duplicate names (dialog error / red border on the inline input)
- Column reorder: plain drag on a header reorders (5 px threshold); Ctrl/Cmd+click renames; clicking a header selects the column via `selectColumns` and sets `win.selectedCol`. Sorting is triggered by clicking the sort button (`.col-sort-btn`, which wraps `.col-badge-sort`) inside `.th-inner`, not by the header click. Ctrl/Cmd+←/→ moves the header-selected column (`win.selectedCol`) from both the global keyboard handler and the per-table `moveSelectionColumns` handler. All paths funnel through `reorderColumn(win, fromIdx, toIdx)`, which splices `tables[name].columns`, re-registers the SQLite table, and calls `rebuildTable(win)`
- Column Manager: dialog subwindow for bulk column reorder (Edit menu, Ctrl/Cmd+Shift+M, or header context menu). Singleton `_activeColManagerWin`. Searchable list, multi-select (click/Shift/Ctrl), drag to reorder or drop onto table headers, Alt+Up/Down moves, double-click scrolls to the column. Internal reorders mutate `t.columns`/`tw.colWidths` directly; `finalizeColManager(winId)` pushes ONE batched `reorderColumn` undo on close by diffing the open-time snapshot. Other windows dim (`applyColManagerDimming`/`clearColManagerDimming`). Global Esc (before the Ctrl/Meta gate in `setupKeyboard`) closes unless focus is in an unrelated input. Dialog subwindows (`opts.dialog`) omit min/max buttons and status bar but ARE resizable/draggable; excluded from edge snapping (`snapPosition`/`getSnapEdges` skip `isDialog`) and `getLayoutUnits()`. Non-modal dialogs stay on top — `raiseDialogs()` (from `focusWindow`, `layoutCascade`, dock mousedown) re-raises `isDialog && !backdropEl` windows. Key functions: `showColManager`, `closeColManager`, `finalizeColManager`

- Find & Replace: `showFindReplace(targetWinId)` opens a non-modal dialog subwindow (singleton `_activeFindWin`, mirrors the Column Manager pattern) targeting one data window; Ctrl/Cmd+F (with a data cell focused, not from other inputs) or Edit menu `#btn-find`. Match state lives on the *target* window — `win._findMatches` (Set of `"rownum:col"` keys) + `win._findCurrentKey` — rendered as `.cell-find-match`/`.cell-find-current` by `applyCellHighlights`. Search runs over `win._displayRows` × `win._columns` against raw values; options: match case, entire cell. Navigation: `scrollCellIntoView(win, di, ci, {smooth:true})` (no focus). Replace/Replace All push one `{ type: 'replace', changes }` undo entry. `getActiveDataWindow()` resolves to the find target while the dialog is active. Cleanup: Esc, `opts.onClose` clears highlights, closing the target window closes the dialog. Tests: `test/integration/find-replace.spec.js`
- Selection statistics: `updateSelectionStats(win)` shows `Count` (non-empty) and `Sum/Avg/Min/Max` (numeric cells, `formatStatNum` = 12 sig digits, en-US) in a `.status-stats` span in `.status-right` when `selectedCells.size >= 2`, replacing the column count; otherwise restores `win._statusRightBase`. `buildTableHTML` sets `win._statusBase` (row count) and `_statusRightBase` instead of writing statusbar textContent directly. Called from `applyCellHighlights` (`selectionDriven` only) and `refocusAnchorCell` (cut/paste/undo/redo). `.status-left`/`.status-right` are `flex: 1 1 0` so the center chips stay perfectly centered regardless of content. Tests: `test/integration/selection-stats.spec.js`
- Toolbar Search/Filter toggle + quick search: `.toolbar-mode` segmented control per table toolbar (`win.toolbarMode`; **'search' is the default**) sharing one `.filter-input` — search highlights without filtering; filter is the SQL WHERE filter (tests typing a WHERE clause must click `.mode-filter` first). All toolbar updates go through `win._applyToolbarMode`/`setToolbarMode(win, mode)` — never write the input value directly. State: `win.searchText`, `win._searchMatchList` (display-ordered keys; its presence marks quick search as owner of the shared `win._findMatches`/`_findCurrentKey` — F&R never sets it; each clears the other on open). Matching = case-insensitive substring, headers first (keys `h:<col>`), then the *displayed* value (`disabledTransforms` guard); recomputed by `buildTableHTML`. Key functions: `runQuickSearch`, `computeQuickSearchMatches`, `quickSearchGoto` (wraps + toast), `focusQuickSearchMatch` (highlights + link rebuilds *before* the smooth focus), `updateSearchCount`, `clearQuickSearch`, `scrollHeaderIntoView`. Smooth scroll: `scrollCellIntoView`/`focusCellAt` take `{smooth, onArrive}` — far targets teleport to within `SCROLL_GLIDE_VIEWPORTS` (1.5) then glide `SCROLL_ANIM_MS` (180ms; off under reduced motion); other callers instant. Keyboard: `/` → `openQuickSearchInput` (temp-switches a Filter toolbar, `win._searchTempRevert`); Enter/Tab focus the current match and set `win._searchNavActive` (grid Tab/Shift+Tab step, Escape refocuses input; cleared by action keys, user focusin, `clearQuickSearch`); a document-level fallback keeps Tab/n/p/Escape working when focus lands on `<body>` mid-glide. Grid Escape outside nav clears search first, selection second. `.filter-clear` Clear button (visibility = input non-empty, set in `updateFilterHighlight`): clears the active mode (search → `clearQuickSearch`; filter → `filterText`/`_filterError` + `rebuildTable`), refocuses the input except on coarse pointers. Tests: `test/integration/quick-search.spec.js`
- Modal dialogs: `createSubwindow` with `opts.modal: true` (+ `dialog: true`) — used by `showPrompt` (Save As, New Table, Insert Column, Open URL) and `showAISettings`. Adds a `.dialog-backdrop` blocking other windows, cancels on mousedown; capture-phase Esc handler (`win._escHandler`). `opts.onClose` fires from `closeWindow` after removal (any window) — `showPrompt` uses it to deliver `null` on cancel (`resolved` flag). `closeWindow` cleans up `backdropEl`/`_escHandler`. Form content wraps in `.dialog-form`; buttons use `.modal-buttons`
- Frozen row-number column: `th.row-num-header`/`td.row-num` use `position: sticky; left: 0`. Table uses `border-collapse: separate; border-spacing: 0` so content doesn't bleed through sticky cells. Z-index: corner 3, row-num/th 2. Sticky highlight overlays use opaque background + inset box-shadow (not rgba)
- Column resize: on first build, `buildTableHTML` auto-fits every column via `autoFitAllColumns(win, AUTO_FIT_LOAD_MAX_ROWS)` (≤5000 display rows), stores px widths in `win.colWidths`, and uses `table-layout: fixed` + `<colgroup>`. Each data `<th>` has a right `.col-resize-handle` and a left `.col-resize-left` (resizes the PREVIOUS column — sticky stacking contexts clip right-side handles). Handles update `<col>` + `win.colWidths` on mousemove without rebuilding. Row-num width is separate (`win.rowNumWidth`, default 50, min 30); `updateTableWidth(win)` keeps table width = rowNumWidth + sum(colWidths). Double-click → `autoFitSelectedOrSingle()` (multi-column selection or clicked column, respecting transforms); `autoFitAllColumns(win)` caps at 75% of pane width; both add `CELL_BORDER` (2px). `reorderColumn`/`insertColumn` keep `colWidths` in sync. Handles set `th._didDrag` on mouseup so the trailing click doesn't select. Multi-column drag resize snaps all selected columns to the dragged width on mouseup
- Column autofilter: each header has an SVG funnel button (`.col-filter-btn`) opening an Excel-style dropdown (`openAutoFilter()`); funnel outline-only, filled (`.active`) when filtering. State: `win.columnFilters` = `{ colName: Set<string> }` — absent key means no filter. `_activeAutoFilter` (module-level) tracks the single open dropdown `{ win, col, el, scrollHandler, anchorEl }`. Lists unique values from ALL rows, with search, Select All, Apply/Clear. Applied in `buildTableHTML()` after the SQL WHERE filter and before sorting — they AND together. `closeAutoFilter()` is called by `buildTableHTML`, resize handles (window and dock), splitter drag, outside click, and Escape. Window resize → `_autoFilterResize`: repositions (`positionAutoFilter`) while focus is inside the dropdown (its search input's soft keyboard fires resize), else closes; coarse pointers don't auto-focus the search input. `renameColumn()` migrates filter entries. Headers use a `.th-inner` flex wrapper (`display:flex` on `th` itself breaks table layout); filtered headers get `.col-filtered`. Virtual scrolling at 200+ unique values. Clicking the Filtered status chip clears all column autofilters and the WHERE filter
- Column sort and the autofilter value list share `compareCellValues(va, vb)` (next to `collator`): numeric-aware — double compare fast path, exact BigInt tie-break when doubles tie for integer strings (>2^53 / past double range), collator fallback. The autofilter list sorts by *raw* value (a formatted display like `$129.50` isn't numeric) while showing display values. Tests: `test/integration/sorting.spec.js`
- Plugin system: JSON configs loaded at runtime controlling per-column display formatting via the CSVSQL expression language (sandboxed evaluator, no JS execution) and cross-table linking. Formats: legacy (`table`/`columns` top-level) and multi-table (`tables` array); optional metadata in the plugin About dialog (singleton `_activePluginAboutWin`). State: `plugins[]` (compiled ASTs), `_columnTransformCache` (tableName → colName → displayAst; rebuilt on plugin load/unload, table open/close/rename, column rename), `_linkCache`. Key functions: `exprTokenize/exprParse/exprEval`, `loadPluginFile/unloadPlugin`, `rebuildTransformCache/rebuildLinkCache`, `getDisplayValue/hasDisplayTransform`, `applyLinkFilters/clearLinkFilters`, `showToast` (`.toast-success`/`.toast-error`, 3s — replaces `alert()`). `renderVisibleRows()` renders `getDisplayValue()`; `enterEditMode()` restores the raw value. Persisted in localStorage `csvsql_plugins`; `.json` drag-and-drop → `loadPluginFile()`. Status chips (order: Linking, Linked, Formatted, Sorted, Filtered): Sorted/Filtered always shown, clear on click; the others appear per `tableIsLinkSource`/`tableIsLinkTarget`/`tableHasTransforms` and toggle `win.disableLinkSource`/`win.disableLink`/`win.disabledTransforms`; inactive chips `.chip-inactive`; shortcuts Ctrl/Cmd+Shift+1 sort, 2 filters, 3 link, 4 format. Headers get `.col-transformed` (+`.feature-disabled`); `.col-badges` holds linking/link/format dots (active filled, inactive `.badge-faint`). All 5 transform call sites (renderVisibleRows, blur, Escape revert, enterEditMode, computeQuickSearchMatches) guard with `!win.disabledTransforms.has(col)`. Autofilter shows formatted values when a transform is enabled; the filter Set stores raw values
- Cross-table linking: plugins define `links` entries with `source`/`target` `{ table, column }` regex patterns. Selecting rows in a source table makes `applyLinkFilters()` (called from `applyCellHighlights()`) collect distinct values from matched source columns and set `win.linkFilters` on target windows — separate from `win.columnFilters`, applied in `buildTableHTML()` after column autofilters. Source table excluded from own targets. Clearing selection calls `clearLinkFilters()`. Propagates transitively via BFS (depth cap 10, cycle-safe). Isolation: `applyCellHighlights(win, selectionDriven)` only calls link functions when `selectionDriven` (direct selection actions pass `true`, `buildTableHTML` rebuilds do not). Re-entrancy guard `_applyingLinkFilters` — chip toggles except Linking set it around `rebuildTable`. `applyLinkFilters`/`clearLinkFilters` rebuild the *source* window too (badges change), restoring a focused cell via `refocusAnchorCell(sourceWin)`. Linking chip toggle explicitly calls `clearLinkFilters`/`applyLinkFilters`. `clearLinkFilters` in `applyCellHighlights` only fires when `win.id === _activeLinkSourceId`
- Touch gestures: touch events only (no pointer events). IIFE-scope state: `_touchHeaderDrag`/`_touchCellDrag`/`_touchWinDrag`, tap trackers `_lastHeaderTap`/`_lastCellTap`/`_lastTitleTap` (keyed by stable identifiers — `rebuildTable` recreates DOM). Cell gesture: first tap records identity+time; second tap within `DOUBLE_TAP_WINDOW_MS` (500 ms) enters `_touchCellDrag` — touchmove > 5 px = drag-select rectangle, else double-tap edit (sets `contenteditable="true"` synchronously, NO preventDefault so the iOS keyboard opens natively). Header drag sets `th._didDrag = true` to suppress the trailing click
- Touch drag bridge: `setupTouchDragBridge()` (document-level capture) re-dispatches single-finger touches on drag handles as synthetic mouse events (`mousedown` on the touched element, `mousemove`/`mouseup` on `document`) so every mousedown-driven drag works by touch unchanged. **Invariant: drag handlers must never require trusted events.** `TOUCH_BRIDGE_SELECTOR`: `.resize-handle`, `.dock-splitter`, `.col-resize-handle`, `#console-resize-handle`, `.dock-tab` (excl. close btn), `.dock-tab-bar`, `.col-manager-grip`, `td.row-num` (pan on row numbers selects, not scrolls). Claims the touch (preventDefault + stopPropagation so 1.5-tap ancestors never see it; skipped while a `_touch*Drag` owns it). Second stationary tap within `DOUBLE_TAP_WINDOW_MS` → `detail: 2` mousedown + synthetic `dblclick` (splitter reset, dock maximize, auto-fit, Column Manager scroll-to). CSS: bridged elements `touch-action: none`, gesture surfaces `-webkit-touch-callout: none` (end of style.css)
- Long-press: `setupLongPress()` — hold `LONG_PRESS_MS` (600 ms, ≤10 px movement) on `td.row-num`/`th.row-num-header`/data `th` → synthetic `contextmenu` at the press point (target re-resolved via `elementFromPoint` if a re-render detached it; fires before the bridged drag's mouseup; touchend preventDefault'ed so the synthesized click can't dismiss the menu; a trusted `contextmenu` — Android native — cancels the timer; presses on `.col-resize-handle` never long-press). Titlebar long-press (no prior tap; `dockHold` in `setupWindowDrag`) hands the touch to the bridge with `shiftKey: true`, driving the unchanged mouse ghost/dock path; tabs undock via the bridged `.dock-tab` drag; a second tap arms `_touchWinDrag`, which blocks `dockHold`
- Coarse-pointer CSS: `@media (pointer: coarse)` (end of style.css) enlarges hit areas via pseudo-element overhangs and un-hides hover-only controls — **never change data row height there** (`ROW_HEIGHT` drives virtual scrolling). `@media (max-width: 640px)` = phone tweaks; windows open maximized below `AUTO_MAXIMIZE_MAX_WIDTH` (700 px) and `createSubwindow` clamps explicit sizes to the workspace. `positionAutocomplete`/`positionAutoFilter` account for the soft keyboard (`visualViewport`; viewport meta has `interactive-widget=resizes-content`). Tests: `test/integration/touch-drag-bridge.spec.js`, `touch-long-press.spec.js`, `test/e2e/touch-dock.spec.js`; shared `dispatchTouch`/`touchCenterOf` in `test/helpers.js`
