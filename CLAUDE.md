# CLAUDE.md

Guidance for Claude Code when working with this repository.

## What This Is

CSVSQL is a browser-based CSV database application. It treats CSV files as database tables with SQL query support, editable cells, and a multi-window interface. No build step or server required — open `index.html` directly in a browser. Also distributed via PyPI (`pip install csvsql`).

## Architecture

Single-page app with three core files:

- **index.html** — Shell: menubar, workspace area, SQL console panel, hidden file input, CDN script tags. File menu order: New Table, Open..., Open (no header)..., Open URL..., Open URL (no header)..., Save Table, Save Table As..., Close Window. Save Table and Save Table As are disabled when no table window is active (non-table windows like Manual, About, Expression Reference don't enable them); Close Window is enabled for any window type. `updateMenuState()` runs at menu-open time and uses `!!t` (table data) for Save/Save As, `!!activeWinId` for Close Window, `hasAny` for layout buttons
- **style.css** — Dark theme styling, window management visuals, table layout
- **app.js** — All application logic in a single IIFE (`app` module), exposing methods on the global `app` object

### Key dependencies (bundled in `lib/`)

All dependencies are self-contained in the `lib/` directory — no CDN or internet required at runtime.

- **Papa Parse** — CSV parsing/unparsing
- **sql.js** — SQLite compiled to WebAssembly; each opened CSV is registered as a SQLite table
- **SheetJS (XLSX)** — Excel file reading/writing
- **JSZip** — ZIP archive support
- **Chart.js** — Inline chart rendering (lazy-loaded on first AI chart)
- **jsPDF + autotable** — PDF report generation (lazy-loaded on first AI PDF)
- **@mlc-ai/web-llm** — In-browser LLM inference via WebGPU (lazy-loaded)

### Data flow

1. CSV opened via File menu → Papa Parse parses → stored in `tables[name]` object (columns, rows, filename, modified flag)
2. Table registered in SQLite via `CREATE TABLE` + batch `INSERT` with prepared statements
3. Edits to cells update `tables[name].rows` and sync back to SQLite via `syncToSQL()`
4. SQL queries run against SQLite; results become new entries in `tables` and open in new subwindows
5. Save serializes `tables[name]` back to CSV via Papa.unparse and triggers browser download

### Window management

Custom subwindow system — each table/query result gets a draggable, resizable, minimizable window inside `#window-area`. Windows are constrained to the workspace area — drag, resize, and keyboard nudge all clamp position and size so windows cannot extend beyond the `#window-area` boundaries. All mouse-driven interactions (window drag, window resize, dock resize, tab drag, splitter drag, column resize, console resize, cell/row selection) require left mouse button only (`e.button !== 0` guard). Right/middle click on data cells calls `e.preventDefault()` to suppress focus and prevent accidental selection. During drag and resize, windows snap to workspace edges and other window edges within `SNAP_THRESHOLD` (10 px). Snap helpers: `getSnapEdges(excludeWin)` collects edge positions from the area and all visible windows, `findSnap(value, edges, threshold)` finds the nearest edge, `snapPosition()` applies snap to both axes during drag, and the resize handler snaps each active edge independently. Blue guide lines (`showSnapGuides`/`hideSnapGuides`) overlay the snap position during the interaction and are removed on mouseup/touchend. The `#snap-guides` container is lazily created inside `#window-area` with `pointer-events: none`. Dragging the titlebar of a maximized window (or the tab bar of a maximized dock) restores its `prevBounds` size via `unmaximizeForDrag()` — the grab point stays proportional; wired into window mouse/touch drag, dock tab-bar drag, and single-tab dock drag; a click without movement does not unmaximize. Resizing a maximized window or dock clears the `maximized` flag. Layout functions (tile, grid, cascade) reposition all visible windows. Windows reposition/resize proportionally when the browser window or console panel is resized (`scaleWindowsToArea()`). Windows track their own sort/filter state and column autofilters. The `windows` array and `tables` object are the two central data structures.

### Tabbing and docking

Windows can be combined into dock containers via tabbing and docking. A dock container is a `.dock-container` element positioned in `#window-area` like a `.subwindow`, with its own resize handles, maximize/minimize support, and a recursive binary split tree for layout.

**Data model:** `dockContainers[]` array holds dock containers. Each has a `root` DockNode — either a leaf (tab group) or a split node. Split nodes have `direction` ('horizontal'|'vertical'), `ratio` (0.0–1.0), and two children. Leaf nodes have `tabs` (array of window IDs), `activeTab`, and DOM references (`el`, `tabBarEl`, `contentEl`). Window objects gain `dockId` (null or dock container ID), `dockLeaf` (reference to containing leaf), and `dockable` (false for help/about windows).

**Tabbing:** Hold Shift and drag a window's titlebar onto another window's titlebar area to merge them into a tab group. Tabs are content-width (fit their text) rather than stretching equally. Only 1 level of tabbing (tab groups cannot be nested inside tab groups, but each pane in a dock split can be its own tab group). The active tab's `.win-body` and `.win-statusbar` are visible; inactive tabs' content is hidden via `display: none` with `dataset.winId` for identification. Double-clicking a tab toggles maximize/restore on the dock container. Single-tab leaves inside a split hide their tab bar (class `single-tab`) but the tab shrinks to content width; the tab bar reappears when a second tab is added. Tabs can be reordered by dragging left/right within the same tab bar (no Shift needed) — the dragged tab dims and a blue insertion indicator shows the drop position. The tab bar has an `::after` pseudo-element providing a minimum 40px grab area to the right of tabs so the dock container can always be moved by dragging the tab bar.

**Docking:** Hold Shift and drop a window onto the body area of another window to create a split dock. Without Shift, dragging just moves the window normally. Drop zone detection uses diagonal-based regions: the body area (below titlebar/tab-bar) is divided into 4 triangular zones by its diagonals — the cursor's position relative to the diagonals determines top/right/bottom/left. Dropping on the titlebar or tab bar triggers tabbing (center zone) with position-aware insertion — `detectDropTarget` computes `tabIndex` from cursor X relative to existing tab midpoints, `showDropOverlay` renders a `.dock-drop-tab-indicator` vertical line at the insertion point, and `dockWindowAsTab(winId, leaf, dock, atIndex)` splices at that position. The overlay shows rectangular half-regions as visual feedback. `getDropZone(x, y, rect, titlebarHeight)` implements the diagonal math using normalized coordinates: `u = bx/bw, v = by/bh` where `bx/by` are relative to the body top-left. Multi-level recursive splitting is supported. The `.dock-splitter` divider is draggable to resize panes (ratio clamped to [0.1, 0.9], double-click resets to 0.5).

**Ghost drag:** For standalone windows, Shift initiates ghost mode at 5px threshold — once activated, releasing Shift does NOT cancel. Ghost matches source size with correct offset. Dropping on valid target docks; empty space moves. Self-drop is a no-op. For tabs, dragging vertically past `TAB_UNDOCK_THRESHOLD` (30px) enters ghost mode automatically (no Shift needed); Shift still works as an immediate override. Horizontal tab drag stays in reorder mode; single-tab leaves move the dock on plain horizontal drag.

**Undocking:** Drag a tab vertically away from its tab bar (past 30px threshold) to undock into ghost mode. The ghost can then be dropped on another window to dock/tab, or on empty space to place as standalone. Retains pane dimensions at drop position. Shift+drag skips reorder and enters ghost mode immediately.

**Dissolve logic:** `removeTabFromLeaf` handles cleanup. Empty leaf → `collapseLeaf` (sibling replaces parent split). Single leaf + single tab → `dissolveDock` (back to standalone window).

**Key functions:** `createDockContainer`, `destroyDockContainer`, `renderDockTree`, `buildDockNodeDOM`, `mergeWindowsIntoTabs`, `mergeWindowsAsSplit`, `dockWindowAsTab`, `dockWindowAsSplit`, `undockWindow`, `removeTabFromLeaf`, `collapseLeaf`, `dissolveDock`, `activateTab`, `renderTabBar`, `setupTabDragFromMousedown`, `setupSplitterDrag`, `detectDropTarget`, `findLeafAtPoint`, `getDropZone`, `showDropOverlay`, `hideDropOverlay`, `executeDock`, `toggleMaximizeDock`, `closeDock`, `getLayoutUnits`, `isWindowMinimized`

**Integration:** `focusWindow` brings the dock container to front and activates the tab. `closeWindow`, `minimizeWindow`, `restoreWindow`, `toggleMaximize`, `nudgeWindow` all delegate to the dock container when the window is docked. Layout functions use `getLayoutUnits()` which includes both standalone windows and dock containers. `scaleWindowsToArea` and `getSnapEdges` include dock containers. `updateWindowTitle` and `startInlineRename` update dock tab titles. Help/about/plugin-about windows are created with `dockable: false`. The dock container's `mousedown` handler walks from `e.target` up to the nearest `.dock-leaf` DOM element, matches it to the dock tree, and calls `focusWindow()` with that leaf's `activeTab` — this ensures `activeWinId` stays correct in split layouts so clipboard operations and `getActiveDataWindow()` target the right pane. `refreshAllTableWindows` closes windows for SQL-dropped tables via `closeWindow` (after clearing the modified flag to skip the prompt) so docked tabs are torn down properly. `undockWindow` clears `maximized`/`prevBounds` since it assigns fresh bounds; `dissolveDock` transfers the dock's maximized state instead. Dock resize handles and splitter drag call `closeAutoFilter()` on mousedown, matching standalone window resize. Minimize acts on the whole dock container, not individual tabs (intentional — undock first for per-window minimize).

### Row identity

Each row's primary key is its `_rownum` property (1-based index). Renumbered on insert/delete. Not a real column — excluded from CSV export.

## Development

No build tools. To develop:

```
python3 -m http.server 8000
# Then open http://localhost:8000
```

Or just open `index.html` directly — all dependencies are bundled locally.

## Testing

Playwright-based test suite (Chromium only). Tests are organized into `test/unit/`, `test/integration/`, and `test/e2e/`.

```bash
# Run all tests (installs deps + browser if needed)
./run-tests.sh

# Run all tests via npm
npm test

# Run a single test file
npx playwright test --config test/playwright.config.js test/integration/sql-queries.spec.js

# Run tests matching a grep pattern
npx playwright test --config test/playwright.config.js -g "filter"
```

The test server runs on port 8274 (auto-started by Playwright config). Tests use `?test=1` query param which sets `window._appReady` after init. Test helpers are in `test/helpers.js` — notably `openApp()`, `uploadFile()`, `executeSQL()`, `waitForWindow()`, and `getTableData()`.

Tests run fully parallel (`fullyParallel: true`, workers = cores−2) — every test must stay independent: open its own page via `openApp()` and never rely on state from another test. Set `PW_WORKERS=1` to debug serially (e.g. `PW_WORKERS=1 npx playwright test ...`). Full suite takes ~1.5 min parallel vs ~10 min serial.

Test fixtures live in `test/` (e.g., `sample1.csv`, `sample.xlsx`, `sample.zip`).

## PyPI Packaging

Published as `csvsql` on PyPI. The Python package in `csvsql/` serves static files via `cli.py`.

**IMPORTANT:** `csvsql/static/` contains copies of the root static files (`app.js`, `index.html`, `style.css`, `lib/`, `example/`). These are NOT auto-synced — whenever you modify any root static file, you MUST copy it to `csvsql/static/` as well, or the `csvsql`/`csvsqlw` command will serve stale files.

```bash
# Sync static files to PyPI package (run after ANY change to root static files)
cp app.js index.html style.css csvsql/static/ && cp lib/* csvsql/static/lib/ && cp -r example csvsql/static/

# Build and publish
rm -rf dist build *.egg-info && python3 -m build
python3 -m twine upload dist/*
```

Version is in `pyproject.toml`.

## Conventions

- All state lives in the `app` IIFE's closure (`windows`, `tables`, `nextWinId`, etc.)
- Public methods are returned from the IIFE and called from HTML onclick handlers or internally
- Test internals are exposed via `app._test` (only used by Playwright tests)
- Table and column names are sanitized to `[a-zA-Z0-9_]` for SQL compatibility
- SQL identifiers use bracket-quoting (`[tableName]`) to handle edge cases
- SQL syntax highlighting uses the overlay technique: a div with highlighted spans behind a transparent textarea/input. The lexer is `sqlTokenize(text)` — `{ type, start, end, text }` tokens (`ws`/`comment`/`string`/`bracket`/`number`/`keyword`/`word`/`op`; `end` exclusive; token texts concatenate back to the input). `sqlHighlightHTML()` is a thin renderer over the tokens. Setup: `setupSQLHighlight()` for the console, inline in `renderTableView()` for filter inputs. The lexer is shared by highlighting and autocompletion — extend `sqlTokenize`, not the renderer
- SQL autocompletion context: `sqlCompletionContext(text, caret, opts)` is pure (no DOM/app state); returns `null` (caret in string/comment/number) or `{ start, end, prefix, items: [{ label, insert, kind }] }` (`[start, end)` = replace range; kind `column`/`table`/`keyword`). `opts.schema` = `{ tableName: [colNames] }`; `opts.filterTable` ranks that table's columns first and drops bare table suggestions (subqueries still get tables after FROM). Detection is lexical, not grammatical, so unknown syntax degrades to broader suggestions: after FROM/JOIN/INTO/UPDATE/TABLE or comma-continued FROM lists → tables; `identifier.` → that table's columns (resolves FROM/JOIN aliases, case-insensitive); SELECT INTO target → nothing (new name); default → columns of statement-mentioned tables (statements split on `;`), then tables, then keywords. Inserts are bracket-quoted when not plain identifiers or when colliding with a keyword. Must never throw for any (text, caret) — fuzz-enforced in `test/unit/sql-completion.spec.js`
- Autocomplete dropdown: `attachAutocomplete(inputEl, getContext)` wires the shared dropdown; attached to `#sql-input` in `setupSQLHighlight()` and each `.filter-input` in `renderTableView()` (before the filter's Escape handler so an open dropdown consumes the first Escape). `getContext` calls `sqlCompletionContext` with a fresh `liveSQLSchema()` snapshot, so schema changes complete immediately. Singleton state: `_acState`, `_acEl` (lazy `#sql-autocomplete` on `document.body`, fixed, z-index 100000), `_acAccepting` (suppresses the input handler during accept's synthetic event). Keyboard contract: CLOSED intercepts nothing except Ctrl/Cmd+Space (explicit open); OPEN — Up/Down navigate, Tab/Enter accept, Escape closes (all `stopImmediatePropagation`), Ctrl/Cmd+Enter closes WITHOUT accepting and falls through to execution. Accept uses `setRangeText` (keeps native undo) + a bubbling `input` event so highlight/filter-debounce run normally. Opens on identifier char, `.`, `[`, or Ctrl+Space; a lone suggestion identical to the typed text is suppressed. Closes on blur/click-in-input/outside mousedown/resize; repositions on scroll. Caret position via `acCaretViewportPos()` (detached mirror div + zero-width-space marker); flips above when near the bottom. `getContext` is try/catch-wrapped — errors degrade to no suggestions. Key functions: `attachAutocomplete`, `tryOpenAutocomplete`, `closeAutocomplete`, `acceptAutocomplete`, `renderAutocomplete`, `positionAutocomplete`, `acCaretViewportPos`, `liveSQLSchema`. CSS: `#sql-autocomplete`, `.ac-item`, `.ac-kind`, `.ac-column/.ac-table/.ac-keyword`. Tests: `test/integration/autocomplete.spec.js`
- Query result tables are registered in SQLite via `registerTable()` so they can be queried and filtered like any other table
- `db.export()` in sql.js destroys custom functions — `registerDBFunctions()` re-registers them after each export
- SELECT INTO is intercepted and handled manually (SQLite doesn't support it natively)
- AI analysis (experimental) uses a SQL tool-use loop: the AI writes SQL in ```sql code blocks, which are executed against SQLite and results fed back (up to 5 rounds). AI can also be used without any tables loaded (general chat mode)
- AI rich output: ```chart (Chart.js config JSON), ```table (columns/rows JSON), ```pdf (document spec JSON) blocks are post-processed into inline charts, HTML tables, and PDF download links. Chart.js and jsPDF are lazy-loaded via CDN on first use. PDFs support text, heading, table, chart, and image content blocks
- AI images: users can drag-and-drop PNG/JPG images onto the AI chat area. Stored in `_aiImages` (name → data URL). Available for inclusion in PDF reports via `{"type":"image","name":"filename.png"}`. Image drop on AI panel is intercepted before the global file-open drop handler
- AI providers: WebLLM (default, in-browser via WebGPU), Ollama (local), Claude (cloud), OpenAI (cloud)
- AI settings (provider, model, API keys) are persisted in localStorage under `csvsql_ai_settings`
- AI conversation history is kept in-memory (`_aiConversation` array) and cleared with the console
- AI prompt history (Up/Down arrow) is in-memory only, not persisted across sessions
- Console tab switching auto-focuses the corresponding input field (SQL input or AI prompt)
- Help windows (Manual, About) are singletons — `showHelpWindow(title, bodyHTML, asDialog)` focuses/restores existing window instead of creating a duplicate. `asDialog: true` creates a dialog-style subwindow (no min/max/resize/statusbar) — used for the short, fixed-content About CSVSQL window; the Manual and Plugin Expression Reference stay resizable
- Cell selection is a rectangle defined by `win.anchorCell` (fixed corner) and the focused cell (lead). Selected cells are cached as a Set of `"rownum:colName"` keys in `win.selectedCells`. Keys use column *names* + `_rownum` so the selection survives sort, filter, column reorder, and rename. `applyCellHighlights()` rebuilds `.row-highlight`/`.col-highlight`/`.cell-selected` classes from this Set after every `renderVisibleRows()` (needed for virtual scrolling). Anchor is reset by user-initiated focusin on a cell; programmatic focus (e.g., drag-end, arrow-key move) sets `win._programmaticFocus` to skip the reset. `selectAllCells(win)` selects every displayed cell and sets `win._copyWithHeader = true`. `selectNoneCells(win)` clears `selectedCells`, `anchorCell`, `_copyWithHeader`, and `selectedCol`. `isAllSelected(win)` returns true when `win.selectedCells.size` equals `displayRows * columns`. The Edit menu has separate "Select All" (Ctrl/Cmd+A) and "Select None" (Esc) buttons. Clicking the `#` corner cell toggles between select-all and select-none. `selectRows(win, fromDi, toDi)` selects entire row ranges, sets `_copyWithHeader`, and clears `selectedCol`. `selectColumns(win, fromColIdx, toColIdx)` selects all cells in a column range and sets `_copyWithHeader = true`. Clicking a column header calls `selectColumns` to select the entire column (Shift+click extends the range); this also sets `win.selectedCol` for Ctrl+Arrow reorder. `selectedCol` is cleared by focusin on a data cell, `selectRows`, `selectAllCells`, and `selectNoneCells` — it is NOT set by the sort badge click or filter button click. Clicking the `#` corner cell (`th.row-num-header`) triggers select-all/none toggle; clicking a `td.row-num` cell triggers row selection (with drag and Shift+click support). `_copyWithHeader` is cleared by the focusin handler on any normal cell click
- Clipboard: `copySelectedCells(win)` reads values from `win.selectedCells`, builds TSV (tab-separated columns, newline-separated rows), and writes to `navigator.clipboard`. For each cell, if a plugin display transform is active and enabled (column not in `win.disabledTransforms`), the formatted value from `getDisplayValue()` is used; otherwise the raw value is used. When `win._copyWithHeader` is true, the column header row is prepended. `cutSelectedCells(win)` copies then clears selected cells (undoable). `pasteAtAnchor(win)` reads TSV from clipboard and fills right and down from `win.anchorCell`, clipping to table bounds. Copy and cut are handled in both the per-table keydown handler (when a data cell has focus) and the global `document` keydown handler (when focus is elsewhere, e.g. column header or titlebar) — edit mode passes through to native browser behavior. After paste/cut/undo/redo re-render the table, `refocusAnchorCell(win)` re-focuses the anchor cell's new DOM node (with `preventScroll`) so the per-table keydown handler continues to receive events without disturbing the scroll position
- Undo/redo stacks (`t._undoStack`, `t._redoStack`) live on the table object (not the window) and are lazily initialized. Cell-level entries use `{ type: 'edit'|'paste'|'cut', changes: [{ rownum, col, oldValue, newValue }] }`. Structural entries use `{ type: 'insertRow'|'deleteRow', rowUndo: { rowIdx, rowData? } }` or `{ type: 'insertColumn'|'deleteColumn', columnUndo: { colName, colIdx, values? } }`. Column rename uses `{ type: 'renameColumn', columnUndo: { oldCol, newCol, colIdx } }`. Column reorder uses `{ type: 'reorderColumn', columnUndo: { oldColumns, newColumns, winId, oldWidths, newWidths } }`. Column resize uses `{ type: 'resizeColumn', columnUndo: { winId, oldWidths, newWidths } }` — pushed by `pushResizeUndo()` from both `startColResize` (drag) and `autoFitSelectedOrSingle` (double-click). Cell-level undo uses incremental `debouncedSync`; structural undo uses `registerTable` (column changes) or full `syncToSQL` (row changes) + `rebuildTable` on all windows. `undoTable(tableName, win)` pops from undo, dispatches to `undoStructural` for structural types or restores cell values for cell types, pushes to redo; `redoTable` is the reverse. New edits clear the redo stack. The Edit menu shows contextual labels ("Undo Delete Column", "Redo Insert Row", etc.) and grays out items when stacks are empty
- Cell editability is a two-state model. Data cells render as `<td class="data-cell" tabindex="0">` — focusable for selection but **not** editable. `enterEditMode(td)` sets `contenteditable="true"`, places the caret at the end, and scrolls the cell to show the caret (`td.scrollLeft = td.scrollWidth`); `exitEditMode(td)` removes the attribute and resets `td.scrollLeft = 0`. In edit mode, CSS enables cell-internal scrolling (hidden scrollbar) to keep the cursor visible. `i`, F2, Ctrl/Cmd+U, Ctrl/Cmd+click, and touch double-tap are the entry points. The blur handler saves + exits edit mode; Escape either reverts the edit (in edit mode) or clears selection (in select mode). Keep the `data-cell` class as the identity check — don't rely on the presence of `contenteditable` to identify data cells
- Arrow-key behavior on a data cell depends on mode: in select mode, plain arrow collapses the selection to the adjacent single cell (`moveSingleCellSelection`), Shift+arrow extends the rectangle (`extendCellSelection`), and Ctrl/Cmd+←/→ moves columns via `moveSelectionColumns` only when `win.selectedCol` is set (i.e., a column was header-selected). In edit mode, Up/Down arrow commits the edit (blur) and moves to the cell above/below in navigation mode; Left/Right arrow passes through to native contenteditable caret movement. Vim keys h/j/k/l are remapped to ArrowLeft/Down/Up/Right before the arrow check (only in select mode, no ctrl/meta/alt), so they funnel through the same `navKey` path as arrows — Shift+H/J/K/L extends. Ctrl/Cmd+H/J/K/L are claimed by `nudgeWindow` (move the active window 5 px in the vim direction), and Ctrl/Cmd+Shift+L/H by `cycleTableWindow` (cycle prev/next visible data window, skipping minimized and non-table windows) — both deliberately bypass the vim nav remap. Tab/Shift+Tab move to adjacent cell left/right in select mode; in edit mode Tab still walks cells in the row. Enter in select mode moves down one row; in edit mode it commits the edit and moves down to the `_editStartColIdx` column in navigation mode (staying on the last row if already there)
- Context menus: right-click a row number for "Insert Row Below" / "Delete Row"; right-click a column header selects the column (via `selectColumns`) and sets `selectedCol` before showing "Insert Column Right" / "Delete Column" / "Manage Columns…"; right-click the `#` corner cell for "Insert Column Right" / "Insert Row Below" (inserts at position 0 — key entry point when table has no rows). All context menus use `showRowContextMenu`, `showColumnContextMenu`, `showCornerContextMenu` and are triggered from the single delegated `contextmenu` listener on `table`. `deleteColumn(tableName, colName)` cleans up `columnFilters`, `sortCols`, `selectedCol`, `colWidths`, `selectedCells`, `anchorCell`, `linkFilters`, and `disabledTransforms` on ALL windows for the table, then calls `registerTable` + `rebuildTable`. Delete Column is disabled when only 1 column remains. `insertColumn(tableName, colName, atIndex)` splices into `t.columns` at the given index, splices a 100px default width into `colWidths` at the same index (preserving existing column widths), and calls `registerTable`. `insertRow(tableName, atIndex)` splices into `t.rows`. All four structural operations push undo entries. Insert column prompts for a name via `showPrompt` with duplicate name validation — the dialog stays open with an error message if the name already exists. `startColumnRename` validates duplicate names inline — the input gets a red border (`#ff6b6b`) on Enter if the name conflicts, and the border clears on the next keystroke
- Column reorder: plain drag on a header reorders (5 px threshold); Ctrl/Cmd+click renames; clicking a header selects the column via `selectColumns` and sets `win.selectedCol`. Sorting is triggered by clicking the sort button (`.col-sort-btn`, which wraps `.col-badge-sort`) inside `.th-inner`, not by the header click. Ctrl/Cmd+←/→ moves the header-selected column (`win.selectedCol`) from both the global keyboard handler and the per-table `moveSelectionColumns` handler. All paths funnel through `reorderColumn(win, fromIdx, toIdx)`, which splices `tables[name].columns`, re-registers the SQLite table, and calls `rebuildTable(win)`
- Column Manager: a dialog-style subwindow (`createSubwindow` with `opts.dialog: true`) for bulk column reorder. Opened via Edit menu, Ctrl/Cmd+Shift+M, or column header context menu "Manage Columns…". Singleton tracked by `_activeColManagerWin` (module-level). Shows a searchable vertical list of all columns with multi-select (click, Shift+click, Ctrl/Cmd+click). Drag to reorder within the list or drop onto table column headers. Alt+Up/Down moves selected columns. Double-click scrolls the table to that column via `scrollTableToColumn`. All internal reorders directly manipulate `t.columns` and `tw.colWidths` (no individual `reorderColumn()` calls) to avoid per-move undo entries. `finalizeColManager(winId)` pushes a single batched `reorderColumn` undo entry on close by comparing against the snapshot taken at open. Other windows are dimmed via `applyColManagerDimming` (`.col-manager-dimmed`: darkening filter + `pointer-events: none`); the target table and manager are excluded. `clearColManagerDimming` removes the class on close. Global Esc handler (before the Ctrl/Meta gate in `setupKeyboard`) closes the column manager unless focus is in an unrelated input/textarea/contenteditable. Dialog subwindows (`opts.dialog`) omit min/max buttons and the status bar but ARE resizable (they keep the 8 resize handles) and draggable; `setupWindowButtons`/`setupWindowResize` null-guard/operate on whichever elements exist. Dialogs are excluded from edge snapping entirely — `snapPosition` early-returns the clamped (unsnapped) position with no guides when `excludeWin.isDialog`, the resize handler uses empty snap edges for dialogs, and `getSnapEdges` skips `isDialog` windows so other windows don't snap to a dialog's edges either. Non-modal dialogs always stay on top of regular windows — `raiseDialogs()` re-raises all non-modal dialog windows (those with `isDialog && !backdropEl`) by bumping z-index; called from `focusWindow` (when focusing a non-dialog), `layoutCascade`, and the dock mousedown fallback. `getLayoutUnits()` excludes `isDialog` windows so tile/grid/cascade don't reposition dialogs. Key functions: `showColManager`, `closeColManager`, `finalizeColManager`, `clearColManagerDimming`, `applyColManagerDimming`

- Modal dialogs: `createSubwindow` with `opts.modal: true` (always combined with `opts.dialog: true`) is the reusable modal dialog component used for prompts (`showPrompt` — Save As, New Table, Insert Column, Open URL) and `showAISettings`. Modal mode adds a `.dialog-backdrop` element (absolute, dims the workspace, appended to `#window-area`) that blocks interaction with other windows and cancels the dialog on mousedown; the dialog is centered in the workspace and gets a higher z-index than the backdrop. A capture-phase `document` keydown handler (`win._escHandler`) closes it on Escape. `opts.onClose` is a callback fired from `closeWindow` after the window is removed — `showPrompt` uses it to deliver `null` (cancel) on backdrop/Esc/X close, guarded by a `resolved` flag so an OK submit doesn't double-fire. `closeWindow` cleans up `win.backdropEl` and `win._escHandler`. Dialog form content is wrapped in `.dialog-form` (padded, scrollable flex column); inputs/selects/buttons reuse `.dialog-form` and `.modal-buttons` styling.- Frozen row-number column: the `#` column (`th.row-num-header` and `td.row-num`) uses `position: sticky; left: 0` so it stays fixed on the left edge during horizontal scroll. The table uses `border-collapse: separate; border-spacing: 0` (not `collapse`) so each cell owns its borders and content doesn't bleed through the sticky cells. Z-index: `th.row-num-header` 3 (corner), `td.row-num`/`th` 2. Sticky highlight overlays use opaque background + inset box-shadow (not rgba) to prevent content showing through
- Column resize: uses a "measure-then-fix" pattern — on first render, columns auto-size in `table-layout: auto`, then `buildTableHTML` measures each `<th>` offsetWidth, stores in `win.colWidths` (array of px values), and switches to `table-layout: fixed` with a `<colgroup>` controlling widths. Each data `<th>` has two resize handles: a right-side `.col-resize-handle` (absolute-positioned div, `right: 0`) whose mousedown calls `startColResize()` for that column, and a left-side `.col-resize-handle.col-resize-left` (absolute-positioned div, `left: -2px`) whose mousedown calls `startColResize()` for the previous column (or `startRowNumResize()` for the first data column). The left-side handle is needed because sticky `th` stacking contexts prevent right-side handles from extending past cell boundaries. Both handles update `<col>` width and `win.colWidths` on mousemove without rebuilding the table. The row-number column (`th.row-num-header`) has only a right-side handle — its width is stored separately in `win.rowNumWidth` (default 50, min 30) and managed by `startRowNumResize()` / `autoFitRowNumColumn()`. `updateTableWidth(win)` keeps the table's inline width in sync with `(win.rowNumWidth || 50) + sum(colWidths)`. Double-click calls `autoFitSelectedOrSingle()`, which checks if the clicked column is part of a multi-cell selection — if so, auto-fits all selected columns; otherwise auto-fits just the clicked column via `autoFitColumn()` (measures header + all displayed rows via off-screen span, respects plugin display transforms). `autoFitRowNumColumn()` handles the row-number column (measures largest row number at 11px font). `autoFitAllColumns(win)` fits every column in one pass — measures all displayed rows, respects plugin transforms, caps at 75% of window/pane width. Both `autoFitColumn` and `autoFitAllColumns` add `CELL_BORDER` (2px) for border-box accounting. `reorderColumn()` splices `win.colWidths` in sync. `insertColumn()` splices a 100px default width into `win.colWidths` at the insertion index, preserving existing column widths (does not reset `rowNumWidth`). The resize handle sets `th._didDrag = true` on mouseup so the subsequent click doesn't trigger column selection (or select-all for the row-num header). Multi-column drag resize: on mouseup, `startColResize` checks `win.selectedCells` for selected columns (union with the dragged column); if multiple, all other selected columns snap to the dragged column's final width. Scroll compensation adjusts `container.scrollLeft` to keep the dragged column's left edge visually stable when left-side columns change width
- Column autofilter: each column header has an SVG funnel button (`.col-filter-btn`) that opens an Excel-style dropdown (`openAutoFilter()`). The funnel is outline-only by default, lights up on `.col-filter-btn:hover`. When a filter is active, `.active` class fills the funnel. State: `win.columnFilters` is `{ colName: Set<string> }` — absent key means no filter. `_activeAutoFilter` (module-level) tracks the single open dropdown `{ win, col, el, scrollHandler }`. The dropdown lists unique values from ALL rows (not filtered rows), with a search box, Select All, and Apply/Clear buttons. Column filters are applied in `buildTableHTML()` after the SQL WHERE filter and before sorting — they AND together. `closeAutoFilter()` is called by `buildTableHTML`, resize handles (window and dock), splitter drag, window resize, outside click, and Escape. `renameColumn()` migrates filter entries. Headers use a `.th-inner` flex wrapper (not `display:flex` on `th` itself, which breaks table layout). Filtered headers get `.col-filtered` class. Virtual scrolling kicks in for 200+ unique values. The Filtered status chip clears all column autofilters and the WHERE filter when clicked
- Plugin system: plugins are JSON config files loaded at runtime that control per-column display formatting via the CSVSQL expression language (a sandboxed evaluator, no JS execution) and cross-table linking. Two formats: legacy (`table`/`columns` at top level) and multi-table (`tables` array). Optional metadata (`version`, `author`, `created`, `description`) shown in the plugin About dialog. State: `plugins[]` (configs with compiled ASTs), `_columnTransformCache` (tableName → colName → displayAst; rebuilt on plugin load/unload, table open/close/rename, column rename), `_linkCache` (compiled link rules). Key functions: `exprTokenize/exprParse/exprEval` (expression language), `loadPluginFile/loadPluginFromFile/unloadPlugin`, `rebuildTransformCache/rebuildTransformCacheForTable/rebuildLinkCache`, `getDisplayValue/hasDisplayTransform`, `applyLinkFilters/clearLinkFilters`, `showPluginAbout`, `showToast`. `renderVisibleRows()` calls `getDisplayValue()` instead of raw `row[col]`; `enterEditMode()` restores the raw value when a transform is active. Persisted in localStorage under `csvsql_plugins`; examples in `example/`. Drag-and-drop of `.json` routes to `loadPluginFile()`. Plugin menu: `.plugin-entry` rows with `.plugin-unload` (✕, menu stays open) and `.plugin-name` (opens About). About is a dialog subwindow, singleton via `_activePluginAboutWin`. `showToast(message, type)` (`.toast-success`/`.toast-error`, 3s auto-dismiss) replaces `alert()` for plugin feedback. Status bar chips: Sorted/Filtered always shown; Linking only when `tableIsLinkSource`, Linked when `tableIsLinkTarget`, Formatted when `tableHasTransforms`. Order: Linking, Linked, Formatted, Sorted, Filtered. Inactive chips get `.chip-inactive` (non-interactive). Sorted/Filtered clear on click. Linked toggles `win.disableLink`; Linking toggles `win.disableLinkSource` (primary: `_activeLinkSourceId`, intermediaries: `win.linkSourceCols`; `updateLinkingChips()` handles cross-window updates; receiving non-empty link filters resets `disableLinkSource`); Formatted toggles `win.disabledTransforms` (Set of column names). Shortcuts: Ctrl/Cmd+Shift+1 sort, 2 filters, 3 link, 4 format. CSS: `.status-chip-sort/filter/link/link-source/format`, `.off`, `.chip-inactive`. Headers get `.col-transformed` (+`.feature-disabled` when suspended). Sort badge `.col-badge-sort` in `.col-sort-btn` inside `.th-inner`: filled triangle when sorted, `.sort-outline` otherwise, multi-sort numbers via `.sort-num`. `.col-badges` container (opaque, centered over `th` bottom border) holds linking/link/format dot badges rendered per-feature; active filled, inactive `.badge-faint`; linking badge lights on outbound-linking columns (`win.linkSourceCols`, populated during BFS); `win.linkDepth`/`win.linkedByDepth` track BFS depth, depth ≥ 2 shows `.badge-numbered`. Helpers: `isLinkSourceColumn`, `linkSourceColsEqual`. `_hasClickHandler` prevents duplicate chip handlers. All 4 transform call sites (renderVisibleRows, blur, Escape revert, enterEditMode) guard with `!win.disabledTransforms.has(col)`. The autofilter dropdown shows display-formatted values when a transform is active and enabled; the filter Set stores raw values
- Cross-table linking: plugins define `links` array entries with `source: { table, column }` and `target: { table, column }` (regex patterns). When rows are selected in a source table, `applyLinkFilters()` (called from `applyCellHighlights()`) collects distinct values from matched source columns and sets `win.linkFilters` on target windows — separate from `win.columnFilters`. Applied in `buildTableHTML()` after column autofilters. Source table excluded from own link targets. Clearing selection calls `clearLinkFilters()`. Link filters propagate transitively via BFS (depth cap 10, `visited` set prevents cycles). Isolation: `applyCellHighlights(win, selectionDriven)` only calls link functions when `selectionDriven` is true (direct selection actions pass `true`, `buildTableHTML` rebuilds do not). Re-entrancy guard (`_applyingLinkFilters`) prevents recursive calls — chip toggles except Linking set this guard around `rebuildTable`. Linking chip toggle explicitly calls `clearLinkFilters`/`applyLinkFilters`. `clearLinkFilters` in `applyCellHighlights` only fires when `win.id === _activeLinkSourceId`
- Touch gestures: touch events only (no pointer-event fallback). State at IIFE scope: `_touchHeaderDrag`, `_touchCellDrag`, `_touchWinDrag`, tap trackers `_lastHeaderTap`/`_lastCellTap`/`_lastTitleTap` (keyed by stable identifiers because `rebuildTable` recreates DOM). Cell gesture: first tap records identity+time; second tap within `DOUBLE_TAP_WINDOW_MS` (500 ms) enters `_touchCellDrag` — if touchmove > 5 px, drag-select rectangle; otherwise double-tap edit (sets `contenteditable="true"` synchronously, does NOT preventDefault so iOS keyboard opens natively). Header drag sets `th._didDrag = true` to suppress trailing click
